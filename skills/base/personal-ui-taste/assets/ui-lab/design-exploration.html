02 ／构图随论点变化

一个主题，三段过程。

第一段 ／准备

等待不是一个
没有解释的数字。

让数量旁边有可追查的条件：资源是否可用、优先级是否合适、依赖是否满足。用户知道下一步该查什么。

当前证据18 条等待还需核对等待时长与原因

第二段 ／执行

把变化放在
它发生的地方。

进度、日志与异常就近展开，不让整个工作台反复进场。解释页面可沿过程移动焦点，高频操作仍保留直接路径。

当前证据8 条运行不以动画速度暗示任务速度

第三段 ／结果

结束以后，
还要能继续判断。

完成只是状态，不代表结果正确。把查看、比较与归档放在结果旁边，让这一段成为下一次操作的起点。

当前证据6 条完成结果质量需另外核验

03 ／细节为动作服务

不必每一块惊艳。
让关键动作完整。

列表重排保留对象，过程切换保留阅读线索，弹层从明确的操作出现。圆角、留白和动效一起服务理解，而不是各自表演。

为什么不是再加一套主题？

这页中性与米色只改变表面；真正的新选择是任务怎样成为主角、每个区块如何组织论点。

哪里可以带回真实产品？

流程解释用于引导与报告；列表/详情联动用于业务操作。可以保留原表格，不必为采用一种新形式把整页推翻。

减少动态效果时会怎样？

布局即时切换、示意直接更新、弹层即时出现。正文和全部演示数据始终可读，静态画面本身成立。

这是内容驱动设计的候选示例，不是新的固定模板。
