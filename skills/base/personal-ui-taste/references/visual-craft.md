# 视觉做法与参考源

2026-10-04：用户强烈认可下列六个参考源，要求选择性吸收，并允许已有主题共同受益。shadcn 的现代简洁方向已进入主题选项；具体配色、字体组合、组件实现与依赖仍按项目选择和目验。

## 按需求使用参考

| 来源 | 吸收的做法 | 在项目中怎么用 |
| --- | --- | --- |
| [shadcn/ui](https://github.com/shadcn-ui/ui) | 组件比例、完整状态、排版、语义 tokens 与源码可修改性 | React 新项目按需采用组件；已有体系借其细节并接入当前 tokens |
| [Radix Colors](https://github.com/radix-ui/colors) | 按用途与状态组织的色阶、明暗与透明色 | 挑所需灰阶/强调/状态色，映射为项目语义变量；不整包塞进页面 |
| [GitHub Readme Stats](https://github.com/anuraghazra/github-readme-stats) | 紧凑摘要卡、标题/指标层级、图标与数值配合 | GitHub README 可直接用其 SVG；业务页面用 HTML/CSS 与现有图表库实现摘要 |
| [Simple Icons](https://github.com/simple-icons/simple-icons) | 品牌与技术生态识别 | 按需引入 SVG 或单个图标；与操作图标分工 |
| [Fontsource](https://github.com/fontsource/fontsource) | 可随项目交付的字体、字重与子集加载 | 需要自托管时按字体/字重导入；已有可靠字体交付方案则复用 |
| [Markdown Badges](https://github.com/ileriayo/markdown-badges) | 图标 + 短文字 + 底色的紧凑标识 | README 使用 Shields.io 徽章；网页采用可访问的原生标签/筛选组件 |

先选页面需要的做法，再选实现。采用组件、字体或素材应有实际用途；不把六个仓库设成每个项目的必装依赖。

具体参考见 [UI lab 组件索引](../assets/ui-lab/README.md)：原生组件、主题 CSS（`themes/`）、字体及图标均随 skill 携带。先定位要用的组件再读源码；下文解释用途，实验室提供可运行起点。新外观不因代码可运行就视为已获用户认可。

## 1. shadcn：让控件组成同一个产品

借其设计细节时，同时检查组件比例和交互状态；只换颜色或圆角不足以复现精致感。

| 部位 | 落地要求 |
| --- | --- |
| 按钮层级 | 主操作用主题 primary；次操作用 secondary/outline；行内轻操作用 ghost；危险操作有明确语义。轻按钮仍需可发现 |
| 对齐与密度 | 同排控件统一高度；文字、图标、箭头对齐；按层级统一 padding/gap，不逐组件随手取值 |
| 表单字段 | label、说明、输入、错误组成字段组；普通/hover/focus/invalid/disabled 有一致表达 |
| 菜单/选择器 | 搜索、选中勾、组标题、分隔与快捷键各有位置；键盘选择、关闭后焦点返回沿用成熟组件行为 |
| 导航 | 当前页面、hover、展开组可辨；对齐图标、文字和计数，避免每行一个厚卡片 |
| 加载与空态 | loading 不让按钮变宽、列表跳动；空态提供对应解释或操作，不靠装饰填满空间 |

- 新 React 项目可按需采用 [shadcn 组件](https://ui.shadcn.com/docs/components)；先看已有项目的版本、样式与底座，避免混用不兼容变体。
- 复用组件的焦点管理和语义行为，再改外观；不只复制截图对应的静态 DOM。
- [shadcn 主题语义](https://ui.shadcn.com/docs/theming)中 `primary` 是主操作；`accent` 常用于 hover/选中表面。映射旧主题的 `accent`（主色）时按用途转换，别只按同名变量机械套值。
- shadcn 的 Chart 基于 Recharts；借其图例/tooltip 设计不要求换掉已有图表库，也不自动满足本 skill 的 T05 焦点联动。

## 2. Radix：从孤立色值变成状态关系

[色阶用途](https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale)是起点；各主题通过[语义别名](https://www.radix-ui.com/colors/docs/overview/aliasing)使用它。

| 阶段 | 典型用途 | 应检查的关系 |
| --- | --- | --- |
| 1–2 | 画布、轻表面 | 页面与面板有层次，但不靠大面积高饱和制造区分 |
| 3–5 | 控件普通、hover、pressed/selected 背景 | 状态变化清楚，选中态不只在 hover 时可见 |
| 6–8 | 弱分隔、交互边界、较强边界/焦点 | 可操作性清楚，静态容器不过度描边 |
| 9–10 | 实色强调与 hover | 成对选择前景文字；黄色等亮色不能默认配白字 |
| 11–12 | 次级与高强调文字 | 辅助文字仍可读；不要用 opacity 一路压暗所有文字 |

- 只引入需要的色系或取其分层方法；原始色阶 → 项目语义变量 → 组件，主题更换时角色不变。
- 中性主题可用深灰 primary；彩色主题可用蓝等主色。品牌、状态、类别、连续量使用各自的配色语义。
- light/dark 使用对应色阶；透明色要按实际底色复验。原色阶的对比说明不保证任意混搭、透明叠加或自定义色都合格。
- 数据系列颜色稳定绑定对象，不因过滤后排序变化而换色；中性界面仍可使用鲜明且可区分的曲线。

## 3. Stats：一张卡概括一个有意义的对象

- 组织：对象/标题 → 主指标及单位 → 时间范围/比较基准 → 次要指标或趋势 → 必要的详情入口。
- 行内用图标、标签、数字对齐帮助扫读；只有可解释的比例才用进度条/环，不照搬与业务无关的等级分数。
- 数值缺测、加载中和真实零值分开；变化箭头带比较基准，数值上涨不自动代表“好”。
- 卡片承载摘要，表格承载密集明细，折线承载趋势；沿用 T11/S03 的图形选择，不为参考卡片改成满页 KPI。
- GitHub Readme Stats 输出 SVG，数据有缓存，公共实例也有限流；适合其支持的数据展示。需要业务筛选、下钻或实时交互时，用现有前端组件实现，不能把图片当成通用交互组件。

## 4. Simple Icons：身份与操作各司其职

- 品牌/技术对象用 Simple Icons；搜索、展开、设置、删除等操作使用项目已有的同一套通用图标，如 Lucide。
- 按需选单个 SVG/导入；统一外框和视觉尺寸，光学校准过细/过满的品牌形状，不整套加载数千图标。
- 密集列表可用协调的单色，品牌色用于需要识别的位置；尊重具体标识用法，不把品牌绿/红误当运行状态。
- 有邻接文字时图标可作装饰；独立图标按钮有可访问名称，tooltip 只补充说明。

## 5. Fontsource：字形选择与交付分开决定

- 先定 UI 正文、标题、数值、代码的角色，再选字体；同一主题通常只需一组协调的 UI 字体，代码单独等宽。
- Inter/Geist 等拉丁字体不能覆盖中文；明确中文配对或系统兜底，并用真实中英混排检查字重、基线、行高与标点。Inter + Noto Sans SC 是候选组合，不是所有主题的强制配对；UI lab 已随页携带 Noto Sans SC 变量切片作为示例。
- 用 Fontsource 自托管可随构建交付；沿用项目已有本地字体或字体优化方案也可以，不重复引入同一字体。
- [安装方式](https://fontsource.org/docs/getting-started/install)：少量固定字重按需导入；需要多档字重时评估 variable 包。普通字形不自动包含 italic。
- 默认生成的 CSS 使用 `unicode-range`，浏览器按页面字符下载相关字集；中文字体仍需看实际请求体积。不要为一个页面打包整套字体库。
- 避免字体加载造成明显布局跳动；为目标平台设可读 fallback。数值对齐用 `tabular-nums`，不因此把名称和正文改为等宽。

## 6. Badges：身份、状态与筛选分开表达

| 角色 | 形态 | 行为 |
| --- | --- | --- |
| 身份 | 品牌/类别图标 + 短名称；中性或适量品牌色 | 展示元信息；有跳转才呈现链接语义 |
| 状态 | 点/符号 + 明文状态；柔和彩色底与可读文字 | 状态实时更新时同步文字，不单靠颜色 |
| 筛选 | 已选条件 + 清楚选中态；可带移除按钮 | 使用真正按钮/checkbox 等语义，支持键盘，取消后内容同步 |

- 同一列表统一标签高度、字重、图标间距与圆角；紧凑表格避免每枚都用高饱和实底抢眼。
- Markdown Badges 主要提供带 Simple Icons 的 Shields.io 用法，常见 `for-the-badge` 适合展示；README 可按需求选 flat 等样式。
- 网页中用 HTML/CSS 组件呈现标签，保留文字、复制与交互能力；不把徽章图片当作按钮或筛选控件。

## 融合后的检查

在所选主题下检查一条真实操作路径：中英长名称与数字、按钮状态、菜单贴边、状态标签、图表焦点和窄屏。把新做法应用到共享组件，避免一页精修、其余页仍旧。

用户认可的是这些参考源及吸收方向；新配对与组件细节在真实页面反馈后再写入演化记录。主题之间共享比例、状态、字体与素材方法，保留各自色调和材质。
