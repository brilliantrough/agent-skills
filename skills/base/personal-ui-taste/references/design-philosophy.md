# 设计哲学与判定

2026-10-08 建立，v3.0 按“主动设计伙伴”修订。提取 taste-skill、huashu-design、ui-ux-pro-max 的方法而非整段搬运：**页面结构、设计机会、构图与交互也是它们的价值，不只是配色和素材**。本 skill 负责把这些方法与有范围的用户反馈结合，见文末分工表。

这份文件回答的是"**该做成什么样、怎么判断好**"；具体外观读 [themes/](../themes/README.md)，具体组件读 [UI lab](../assets/ui-lab/README.md)，具体场景读 [scenarios/](../SKILL.md)。

## 一、顺序：先有判断，再做表达

| 步 | 做什么 | 完成标志 |
| --- | --- | --- |
| 1 读题 | 判断操作/阅读/比较/展示，读实际内容、品牌与现有页面 | 一行“为谁解决什么，建议怎样表达” |
| 2 找机会 | 从已有形式中找阅读、比较或操作的阻力，不只挑颜色问题 | 一个有具体收益的改善点；没有就不硬加 |
| 3 取方法 | 读对应场景与外部方法，核对推荐是否真正适配；拨盘按需使用 | 能说明形式、技术与参考的边界 |
| 4 看关键区块 | 方向未定时给三个真实差异方向；参考已定或用户委托选择时直接推荐合适构图 | 用户可看的区块/草稿，不只风格名；明确小修跳过此步 |
| 5 落地 | 静态构图 → 真实状态 → 适当动效；复用共享层 | 可运行页面，数据/资源占位明确 |
| 6 自审 | 概念与机会 + 执行细节 + 一条真实路径 | 技术结果与审美认可分别报告 |

不是每次都重走一套重装流程。局部改动按范围修；整页探索才做方向比较与关键区块预览。

## 二、三拨盘：把"多大程度"变成数字

需要讨论强度时用三个 1–10 的档，作为沟通语言；局部修复无需报分，数字也不是质量评分：

- **变异 DESIGN_VARIANCE**：1 = 完全对称规整；10 = 不对称、破格、有作者痕迹
- **动效 MOTION_INTENSITY**：1 = 静态；10 = 电影级、物理感
- **密度 VISUAL_DENSITY**：1 = 画廊式留白；10 = 驾驶舱式密集

基线 **3 / 3 / 6** 只适用于浅色工作型界面（规整、短反馈、中等密度），不是展示/阅读/报告的默认值。按任务推断：

| 用户的话 | 变异 | 动效 | 密度 |
| --- | --- | --- | --- |
| "极简 / 干净 / 安静 / 编辑感 / Linear 那样" | 4–5 | 2–3 | 3–4 |
| "高级 / 消费级 / 苹果感 / 品牌感" | 6–7 | 4–5 | 3–4 |
| "有意思 / 大胆 / Awwwards" | 8–9 | 6–8 | 3–4 |
| "信任优先 / 政务 / 合规 / 可访问性关键" | 2–3 | 1–2 | 5–6 |
| 改造已有界面（保结构） | 跟随现状 | 只修缺失反馈，不自动加一级 | 跟随任务 |

沟通参考：密集管理台 3/2/7；文档站 3/2/4；产品叙事 6/5/4；大胆视觉作品 8/6/3。作品集也可以安静，不能仅凭页面名称推断强度。

拨盘用于察觉失配，不是压低探索的闸门：高密度明细仍可有舒展的概览；工作控件短反馈与解释区滚动呈现可在一页共存。数字不写进代码，不为提高分数加花样。

## 三、从内容长出一个设计想法

1. **继承识别度，重新判断形式**：品牌物料、设计系统、截图与源码是起点，不是照搬现有构图的理由。问旧形式服务了什么、又遮住了什么。
2. **没有上下文也能提出好方案**：按内容、受众与媒介推导，检索合适参考，再给可看的候选。不要把缺参考当不能设计，也不要把参考库当答案库。
3. **一个主意，几种构图**：例如“先看堵点，再看路径，最后查明细”。统一色板/字体/组件，按区块换主角、比例与密度；像 PPT 一段一个论点，但不强制等高全屏。
4. **先设计静态画面，再编排变化**：让关键停顿帧有清晰焦点、信息与下一步。一个核心交互精修，其他部分安静；不平均给每块加特效。
5. **具名品牌真实呈现时取真实资产**：可见的 logo、产品图不手画近似；资源暂缺可诚实占位。仅提到参考站名不要求插入其 logo。
6. **不虚构来填空**：真实数据有缺口就标明；原型可用明确标注的演示数据。构图、留白与阅读节奏本身可以完成表达。

## 四、真系统 vs 审美方向（诚实规则）

| 如果需求读起来像 | 用 | 规则 |
| --- | --- | --- |
| 微软、Material、IBM、Shopify、Atlassian、GitHub、政务或现代 SaaS 等明确系统 | Fluent UI / Material / Carbon / Polaris / Atlaskit / Primer / GOV.UK / USWDS / Radix / shadcn 等 | 需要该系统的组件能力时用官方实现；仅借视觉气质时沿用现有技术栈并标明是参考。一个项目保持一致体系，不混搭两套相互冲突的规则 |

| 如果需求是一种气质 | 做法 |
| --- | --- |
| 玻璃、Bento、布鲁塔、编辑杂志、暗色科技、极光/网格渐变、动态排版 | 没有官方包，用原生 CSS + 成熟组件库自己搭；在代码注释里说明哪些是参考、哪些是原创 |

参考不是实现：原生 HTML 可以学习 shadcn 的比例、层级与状态，不冒称安装了官方 React 组件；React 项目需要这些组件时再采用官方源码。

## 五、反 AI 味：宁可少做，也不要默认

**为什么反**：AI 的默认产出等于训练语料的平均视觉，也就是所有品牌混在一起——结果没有任何品牌被认出来。反 slop 不是审美洁癖，是替用户保护识别度。

**这些是审查提示，不是禁用目录。** taste-skill 主文件面向落地页、作品集与改造，明确不是数据看板规范；本 skill 借其 `redesign-skill` 的审查维度，不照搬字体禁令、破格排版、惯性滚动或装饰纹理。用户明确喜欢的中性、米色、普通网格都可以成立。

| 类别 | 默认不要 | 为什么 | 何时可以 |
| --- | --- | --- | --- |
| 表面 | 紫色/多色极光渐变、霓虹外发光、纯黑 `#000000`、大面积玻璃叠玻璃 | 语料里"科技感"的万能公式，不携带信息；纯黑压死层次 | 品牌本身就是；暗场叙事要的是有作者意图的暗色（暖色竞速、电影级打光），不是均匀深蓝 + 通用霓虹 |
| 卡片 | 每个数值或每一行都套框，边框与阴影同时争层级 | 容器比内容显眼，页面像组件拼盘 | 有独立操作、预览、可拖动或需区分范围时使用卡片；静态总览可用开放式读数 |
| 图形 | 用通用剪影或自画近似图冒充真实品牌/产品资产 | 真实产品信息失真，装饰替代证据 | 原创解释图、过程示意、数据图可以使用；真实资产未取到则诚实占位 |
| 字体 | 不管中英配对与字重、标题一味放大、所有小标题与数字都用衬线 | 不同信息争夺注意力，数据扫读变慢 | Inter 与平色适合中性产品；衬线用于明确的阅读/纸面方向，控件与数据仍可无衬线 |
| 布局 | 三张等宽卡片一行、控件不对齐、间距随手取值 | 通用 feature row 是默认模板；不齐是"没做完"的信号 | 有意的对称或对齐系统 |
| 内容 | 编数字（99.99%、50%）、Jane Doe/张三样例、Acme/Nexus 式命名、"赋能/无缝/下一代" | 假数据比没有数据更误导，slop 文案稀释可信度 | 明确标注为演示数据 |
| 动效 | 到处 hover 放大、滚动劫持、进场动画拖慢操作 | 动效是解释因果的，不是装饰 | 叙事型页面的关键节点；始终遵守 `prefers-reduced-motion` |
| 资源 | 依赖不稳定的图床、整包引入图标库 | 页面会坏；体积不可控 | 稳定占位图源、按需引入 |

**正向做法**：先比较参考与页面的视觉重心、内容宽度、文字层级和容器密度，不只比 hex。静态读数不加无数据支撑的小波形；同一指标的分类柱可共用一色，多色留给可区分的数据系列与状态。平色、对齐与留白本身就是设计，不必加纹理证明“做过设计”。

**反例要隔离**：如果任务本身就是讲反设计（评测、对比、"什么不要做"），把反例放进带虚线框与"反例 · 不要照做"角标的容器里，不要让整页真的变成 slop。

## 六、审查协议：审自己，也审别人的界面

审 UI 时**先审概念与机会**：页面是否有来自内容的想法？什么信息值得成为主角？有没有更直观的表示却被旧样板挡住？工作控件不必独创，但表达/展示区不能只换客户名和颜色。再按下表审执行；不使用主观评分伪装成用户认可。

| 维度 | 看什么 |
| --- | --- |
| 排版 | 中英混排字重/基线/标点；层级靠字重与颜色而非一味放大；测度（长文 60–75 字符）；数字 `tabular-nums` |
| 色彩与表面 | 每个颜色有角色（画布/表面/边界/强调/状态/数据）；层次靠灰阶与发丝线；状态色不被强调色吃掉 |
| 布局 | 对齐与间距成系统；操作距离（筛选靠近被控对象）；窄屏不塌；内容决定骨架，不是先摆卡片 |
| 交互与状态 | 不止样子：筛选是否真的改数据，选对象是否同时更新标题/数值/状态，空态是否可恢复；hover/focus/pressed/selected/disabled 可辨，键盘可达 |
| 内容 | 无编造数字与占位人名；单位和时间范围明确；文案不用 slop 词 |
| 组件 | 同排控件等高、间距统一；图标尺度统一；不混两套系统 |
| 图标 | 品牌与操作图标各司其职；独立图标按钮有可访问名称 |
| 代码 | token 化而非硬编码；改共享层而非堆覆盖；无 `!important` 掩盖冲突 |

**战略性的遗漏**（AI 常忘）：空态、加载、错误、禁用、键盘、窄屏、长名称、极端值、深色配对、打印/导出。审的时候专门去点这些。

**动效按区块目的分工**：工作操作短反馈；阅读/展示可有滚动章节、对象连续性、关键证据分批呈现。两者见 [motion.md](motion.md)，不把宣传短片的停顿套到搜索/编辑，也不因页面含表格就禁止其他区块的表达。

**边界**：技术验证通过（能跑、无报错、对比度合格）不等于审美已认可；反之亦然。用户认可的区间按 [evolution.md](../evolution.md) 记录。

## 七、与已安装 skill 的分工

| 需要什么 | 去哪 |
| --- | --- |
| 产品与页面结构、UX/图表建议、动效预设、技术栈指导与风格目录 | `ui-ux-pro-max`：按问题查 `product` / `landing` / `ux` / `chart` / `gsap`，整页新方向可用 `--design-system`；核对结果，不盲从行业预设 |
| 高保真原型、场景构图、静态关键帧、叙事节奏、动画/视觉 QA | `huashu-design`：原型/幻灯片/动画的方法源，不冒称生产 Web App 规范 |
| 正向模式词汇、开篇/网格/滚动表达、反默认与改造审查 | `taste-skill`：参考主文件 §10–12 与 redesign；现有安装缺失时查上游或临时克隆，不将落地页禁令照搬到工作台 |
| 主动推荐、个人反馈范围、真实业务交互、适用判断 | 本 skill |

调用原则：**个人偏好只覆盖其实际范围，外部方法不是只配提供素材。** 有明确反馈的同一处理以该反馈为准；新场景、未确认的构图可吸收外部方法或原创推导，并用预览求证。必要外部 skill 未装时如实说明、读取可用参考或用原生能力，不静默假装调用。

本轮提取方法、不复制第三方代码：来源均为 MIT，仓库入口分别为 [UI/UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)、[Huashu Design](https://github.com/alchaincyf/huashu-design)、[Taste Skill](https://github.com/Leonxlnx/taste-skill)。
