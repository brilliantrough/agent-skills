# 设计哲学与判定

2026-10-08 建立。内容从三份公共 skill（taste-skill、huashu-design、ui-ux-pro-max，均为 MIT）与线上实测中提取**判定逻辑**，改写成本 skill 的语气；不整段搬运，也不与它们争当第二套裁判。需要深水内容（79 种风格的完整 token、动画配方、视觉 QA 脚本）时直接调用那两个已安装的 skill，见文末分工表。

这份文件回答的是"**该做成什么样、怎么判断好**"；具体外观读 [themes/](../themes/README.md)，具体组件读 [UI lab](../assets/ui-lab/README.md)，具体场景读 [scenarios/](../SKILL.md)。

## 一、顺序：六步，可以回头但不要跳

| 步 | 做什么 | 产出 |
| --- | --- | --- |
| 1 读题 | 内容是给谁看的、要完成什么判断、有没有既有品牌/设计系统/截图/代码 | 一行"设计判断"，写进交付说明 |
| 2 定三拨盘 | 变异 / 动效 / 密度（见下节） | 三个数字，作为后续所有取舍的闸门 |
| 3 选地基 | 沿用现有体系；需要组件能力时用官方组件，风格参考不强制迁移框架 | 明确组件与参考的边界 |
| 4 出方向 | 无既有参考时给三个**真实差异**的方向让用户挑 | 三份可看的东西，不是三种配色 |
| 5 落地 | 先占位后实现；改共享层再改单页 | 可运行页面 + placeholder 清单 |
| 6 自审 | 反 AI 味清单 + 一条真实操作路径复验 | 审查结论（技术通过 ≠ 审美认可） |

跳过第 1、2 步是最常见的失败：直接开始摆卡片，最后发现密度、动效强度、导航位置都不对，返工代价远大于先问一句。

## 二、三拨盘：把"多大程度"变成数字

开工前定三个 1–10 的档：

- **变异 DESIGN_VARIANCE**：1 = 完全对称规整；10 = 不对称、破格、有作者痕迹
- **动效 MOTION_INTENSITY**：1 = 静态；10 = 电影级、物理感
- **密度 VISUAL_DENSITY**：1 = 画廊式留白；10 = 驾驶舱式密集

基线 **3 / 3 / 6**（浅色工作型界面：规整、短反馈、中等密度）。按任务推断，不为提高分数而加花样：

| 用户的话 | 变异 | 动效 | 密度 |
| --- | --- | --- | --- |
| "极简 / 干净 / 安静 / 编辑感 / Linear 那样" | 4–5 | 2–3 | 3–4 |
| "高级 / 消费级 / 苹果感 / 品牌感" | 6–7 | 4–5 | 3–4 |
| "有意思 / 大胆 / 作品集 / Awwwards" | 8–9 | 6–8 | 3–4 |
| "信任优先 / 政务 / 合规 / 可访问性关键" | 2–3 | 1–2 | 5–6 |
| 改造已有界面（保结构） | 跟随现状 | 只修缺失反馈，不自动加一级 | 跟随任务 |

预设参考：仪表盘/管理台 3/2/7；文档站 3/2/4；落地页 6/5/4；作品集 8/6/3。

拨盘的作用是**否决**：密度 7 的看板不要用大留白卡片；动效 2 的产品不要上滚动劫持。数字不写进代码，写进判断。

## 三、从哪长出来（最硬的一条）

1. **有既有上下文就从那里长**：品牌物料、现成设计系统、截图、代码库。凭空做高保真是最后手段，产物一定是通用货。
2. **没有上下文时不要凭直觉硬做**：进入 [风格菜单](style-menu.md) 流程，给三个方向让用户挑。
3. **出现具名产品/品牌时，官方 logo 与产品图是必需资产**，不是"有就用"。设计里能认出某个产品，就得取它的真实资产；取不到就留诚实占位，不要手画一个近似的 Logo。
4. **Placeholder 优于烂实现**：没有图标就留灰块加文字，没有数据就写注释。一个诚实的占位比一个拙劣的真实尝试好得多。
5. **不要填充**：每个元素都要挣到自己的位置；用构图解决空白，不要靠编数字、编图标、编渐变填满。

## 四、真系统 vs 审美方向（诚实规则）

| 如果需求读起来像 | 用 | 规则 |
| --- | --- | --- |
| 微软、Material、IBM、Shopify、Atlassian、GitHub、政务或现代 SaaS 等明确系统 | Fluent UI / Material / Carbon / Polaris / Atlaskit / Primer / GOV.UK / USWDS / Radix / shadcn 等 | 需要该系统的组件能力时用官方实现；仅借视觉气质时沿用现有技术栈并标明是参考。一个项目保持一致体系，不混搭两套相互冲突的规则 |

| 如果需求是一种气质 | 做法 |
| --- | --- |
| 玻璃、Bento、布鲁塔、编辑杂志、暗色科技、极光/网格渐变、动态排版 | 没有官方包，用原生 CSS + 成熟组件库自己搭；在代码注释里说明哪些是参考、哪些是原创 |

参考不是实现：原生 HTML 可以学习 shadcn 的比例、层级与状态，不冒称安装了官方 React 组件；React 项目需要这些组件时再采用官方源码。

## 五、反 AI 味：宁可少做，也不要默认

**为什么反**：AI 的默认产出等于训练语料的平均视觉，也就是所有品牌混在一起——结果没有任何品牌被认出来。反 slop 不是审美洁癖，是替用户保护识别度。

**这些是审查提示，不是禁用目录。** taste-skill 主文件面向落地页、作品集与改造，明确不是数据看板规范；本 skill 借其 `redesign-skill` 的审查维度，不照搬字体禁令、破格排版、惯性滚动或装饰纹理。用户明确喜欢的中性、米色、普通网格都可以成立。

| 类别 | 默认不要 | 为什么 | 何时可以 |
| --- | --- | --- | --- |
| 表面 | 紫色/多色极光渐变、霓虹外发光、纯黑 `#000000`、大面积玻璃叠玻璃 | 语料里"科技感"的万能公式，不携带信息；纯黑压死层次 | 品牌本身就是；暗场叙事要的是有作者意图的暗色（暖色竞速、电影级打光），不是均匀深蓝 + 通用霓虹 |
| 卡片 | 每个数值或每一行都套框，边框与阴影同时争层级 | 容器比内容显眼，页面像组件拼盘 | 有独立操作、预览、可拖动或需区分范围时使用卡片；静态总览可用开放式读数 |
| 图形 | SVG 手画人物/产品/场景、用剪影代替真实产品图 | 生成的一定是"通用科技动画"，品牌信息归零 | 几乎没有；宁可留占位或标"待补" |
| 字体 | 不管中英配对与字重、标题一味放大、所有小标题与数字都用衬线 | 不同信息争夺注意力，数据扫读变慢 | Inter 与平色适合中性产品；衬线用于明确的阅读/纸面方向，控件与数据仍可无衬线 |
| 布局 | 三张等宽卡片一行、控件不对齐、间距随手取值 | 通用 feature row 是默认模板；不齐是"没做完"的信号 | 有意的对称或对齐系统 |
| 内容 | 编数字（99.99%、50%）、Jane Doe/张三样例、Acme/Nexus 式命名、"赋能/无缝/下一代" | 假数据比没有数据更误导，slop 文案稀释可信度 | 明确标注为演示数据 |
| 动效 | 到处 hover 放大、滚动劫持、进场动画拖慢操作 | 动效是解释因果的，不是装饰 | 叙事型页面的关键节点；始终遵守 `prefers-reduced-motion` |
| 资源 | 依赖不稳定的图床、整包引入图标库 | 页面会坏；体积不可控 | 稳定占位图源、按需引入 |

**正向做法**：先比较参考与页面的视觉重心、内容宽度、文字层级和容器密度，不只比 hex。静态读数不加无数据支撑的小波形；同一指标的分类柱可共用一色，多色留给可区分的数据系列与状态。平色、对齐与留白本身就是设计，不必加纹理证明“做过设计”。

**反例要隔离**：如果任务本身就是讲反设计（评测、对比、"什么不要做"），把反例放进带虚线框与"反例 · 不要照做"角标的容器里，不要让整页真的变成 slop。

## 六、审查协议：审自己，也审别人的界面

审 UI 时按维度走一遍，不要只说"感觉不错"。每维给结论 + 具体位置；发现的问题按"先结构后皮肤、先路径后美观"排序。

| 维度 | 看什么 |
| --- | --- |
| 排版 | 中英混排字重/基线/标点；层级靠字重与颜色而非一味放大；测度（长文 60–75 字符）；数字 `tabular-nums` |
| 色彩与表面 | 每个颜色有角色（画布/表面/边界/强调/状态/数据）；层次靠灰阶与发丝线；状态色不被强调色吃掉 |
| 布局 | 对齐与间距成系统；操作距离（筛选靠近被控对象）；窄屏不塌；内容决定骨架，不是先摆卡片 |
| 交互与状态 | 不止样子：筛选是否真的改数据，选对象是否同时更新标题/数值/状态，空态是否可恢复；hover/focus/pressed/selected/disabled 可辨，键盘可达 |
| 内容 | 无编造数字与占位人名；单位和时间范围明确；文案不用 slop 词 |
| 组件 | 同排控件等高、间距统一；图标尺度统一；不混两套系统 |
| 图标 | 品牌与操作图标各司其职；独立图标按钮有可访问名称 |
| 代码 | token 化而非硬编码；改共享层而非堆覆盖；无 `!important` 掩盖冲突 |

**战略性的遗漏**（AI 常忘）：空态、加载、错误、禁用、键盘、窄屏、长名称、极端值、深色配对、打印/导出。审的时候专门去点这些。

**动效**：工作界面只做操作后的短反馈；弹层进入、内容切换、按需展开见 [motion.md](motion.md)。一条真实操作路径比一屏循环动画更能说明“好用”。

**边界**：技术验证通过（能跑、无报错、对比度合格）不等于审美已认可；反之亦然。用户认可的区间按 [evolution.md](../evolution.md) 记录。

## 七、与已安装 skill 的分工

| 需要什么 | 去哪 |
| --- | --- |
| 风格/配色/字体目录（79 种风格含完整 token、192 个产品配色、74 组字体配对、119 条 UX 规则、17 个动效预设），按需求检索设计系统 | `ui-ux-pro-max` skill（已全局安装，数据在 `data/`） |
| 动效叙事与缓动理论、GSAP 配方与动画反例、视觉 QA 脚本、幻灯片与短片流程 | `huashu-design` skill（已全局安装） |
| 个人偏好、场景规则、皮肤库、可运行组件、本审查口径 | 本 skill |

调用原则：**先定判断（本文），再取素材（它们）**。两份外部 skill 的规则与本文冲突时，以本 skill 的用户偏好为准——它们给的是通用平均，本 skill 记录的是这位用户的实际认可范围。
