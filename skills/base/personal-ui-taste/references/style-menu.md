# 形式与风格菜单：从内容推导，不从模板挑皮肤

2026-10-08 建立，v3.0 扩展正向设计方法。先问内容要怎样被理解和使用，再决定构图、交互、动效与表面。本文件是灵感词汇，不是可用形式的全集；合适的新形式可以来自外部参考或 Agent 推导。

## 一、先说话，再选库

| 情况 | 做法 |
| --- | --- |
| 用户给了品牌、设计系统、截图、参考站点 | 保留其识别度，仍主动推导适合本内容的新构图；借参考的原则，不把参考的每个布局当命令 |
| 什么都没有，需求模糊（“做个好看的”） | 给三个真实差异方向与推荐：同时说明结构、内容主角、关键交互与节奏，不是同一套配色的三个色相 |
| 已有界面要改造 | 先审概念、机会与实际路径；保留有效部分，对明确授权的范围做更合适的表达 |

每个方向说清：帮助看懂什么、视觉主角/关键区块怎样排、用户怎样操作、代价是什么。给关键区块的示意、可逆预览或真实参考；选定后不反复询问，发现不适配可解释并建议调整。

## 二、色彩推导协议（三步）

需要建立或调整色彩体系时，用这三步支撑判断；已有品牌不重复取色，没有参考也可以提出有角色与对比度依据的原创方案：

1. **取依据**：优先品牌物料、实物照片或截图；没有这些时从内容气质与语义角色出发，给可看的候选，不冒称来自真实采样。
2. **收敛**：统一灰阶与色温，限制装饰色。纸面方向可降饱和；shadcn 式产品可用纯白和中性文字；数据/状态保持可区分性。不把“低饱和”或“禁止纯白”当普遍高级公式。
3. **论证**：每个颜色回答"它代表什么角色"：画布 / 表面 / 边界 / 文字 / 强调 / 状态 / 数据系列。说不出角色就不要这个颜色。

同色相在不同语境里含义不同，取色前先确认语境（红：警示 / 喜庆 / 品牌；绿：成功 / 生态 / 金融下跌；白：干净 / 丧葬 …）。要更多风格与色彩参考时读 `huashu-design` 的 `references/design-styles.md`（网页/PPT/信息图各 20 种，含色彩推导协议与文化语境速查）。

## 三、正向设计模式：什么时候值得主动推荐

先说收益再说名字。下表是提案词汇，不要求每页都使用；一页精修一个有意义的主角即可。

| 内容机会 | 可以提的形式 | 收益与边界 |
| --- | --- | --- |
| 结论藏在大量明细里 | 结论引导开篇 + 证据旁注 + 渐进展开 | 先读懂，再查证；结论有数据来源，不编效果数字 |
| 需要解释过程/方法 | 章节式叙事、Sticky-Stack、固定示意 + 步骤切换 | 一段一个论点，过程对象连续；自然滚动与静态阅读仍完整 |
| 两方案只有长文字描述 | 并排同口径、前后切换、差异高亮 | 把差别直接展示；不要把阅读顺序/数据口径也换掉 |
| 产品能力被写成 feature 清单 | 一个可操作的真实流程演示 | 做一次就懂；交互确实改内容，演示/生产状态明确 |
| 图片/成果是核心内容 | 非对称图文、编辑式画廊、Masonry、主图 + 注释 | 用作品当主角；不把每张图硬塞进等宽功能卡 |
| 持续在多个对象间跳转 | Master-detail、共享对象布局过渡 | 位置关系和上下文连续；保留选择/筛选与键盘焦点 |
| 对象在时间中改变 | 可展开时间线、步骤路径、局部重放 | 因果顺序可追踪；不默认自动播放或虚构进度 |
| 主要问题是关系/流向 | 矩阵、Sankey/Alluvial、可下钻关系图 | 关系先于独立总计；精确数值保留列表/表格与键盘替代 |
| 多张曲线难以比较 | 同轴小多图、局部聚焦、统一图例 | 保留科学比较；按 S03 范围继承，不为新颖而换掉已认可折线 |
| 长表单一次暴露太多 | 步进流程、渐进披露、内联反馈 | 减少当前负担；简单任务不人为增加步骤 |
| 宣传/作品需要记忆点 | 非对称开篇、编辑宣言、短标题揭示、媒体遮罩 | 内容/真实资产决定视觉母题；不搬到高频数据控件 |
| 所有区块都一样 | 同主题、多构图、多密度的章节节奏 | 一致的是字体/色板/状态，不是每块都套同一张卡 |

需要完整设计/实现方法时读已安装的 `design-taste-frontend`；高保真构图/叙事读 `huashu-design` 的当前入口，分工见 [外部设计能力](external-skills.md)。上述是本 skill 提炼的适配词汇，不逐版镜像上游章节，也不把磁吸按钮、滚动劫持或每次三方向硬门默认带入所有场景。

**“PPT 感”应理解为清晰论点与构图节奏**：一段讲一件事，主角/证据/过渡分工；不是每段全屏、每字飞入。演示候选见 [design-exploration.html](../assets/ui-lab/design-exploration.html)，常规业务操作仍可以紧凑。

### 用 UI/UX Pro Max 验证候选

它提供产品/页面结构、UX、图表、动效与视觉检索。2026-10-08 的接口以 `gsap` 查询动效，而不是 `motion`；上游更新后以其实际 SKILL.md 和脚本帮助为准，不在本仓维护库的条目数。

读取实际安装的 skill 再调用其脚本；下面用常见全局目录示例，不假定某个宿主的插件变量：

```bash
skill="$HOME/.agents/skills/ui-ux-pro-max"
python3 "$skill/scripts/search.py" "scroll storytelling" --domain landing -n 2
python3 "$skill/scripts/search.py" "interactive demo" --domain landing -n 2
python3 "$skill/scripts/search.py" "analytics dashboard" --domain product -n 2
python3 "$skill/scripts/search.py" "relationship flow" --domain chart -n 2
python3 "$skill/scripts/search.py" "scroll reveal stagger" --domain gsap -n 2
```

新产品/整页新方向可用 `--design-system`，定向问题用单个 `--domain`，技术栈从项目检测后用 `--stack`；不要每次把所有域都跑一遍，也不未经确认 `--persist --force` 覆盖已有设计体系。

- 读命中的具体模式、`Section Order`、`When to Use`、强度与退化方案，不只读推荐风格名
- BM25 的词语命中不保证语义适配：本轮 `progressive disclosure` 返回标题换行条目，不能据此声称查到了渐进披露规则；收窄重查一次，仍不适配就标为自身设计判断
- 行业预设不等于个人需求；不能因为推荐金融看板深色，就覆盖用户当前要求的浅色
- 命中复杂动效不等于应该加库；先考虑原生、既有依赖与静态退化，照顾触摸、键盘及减少动态效果

## 四、四种工作型骨架样本

选主题之前先选合适形式。下表只覆盖常见工作型结构，**不是四选一上限**；章节叙事、编辑画廊等见上节：

| 骨架 | 长什么样 | 适合 | 风险 |
| --- | --- | --- | --- |
| 侧栏 + 主栏 | 左导航常驻，右侧单栏内容 | 多页面工作台、导航项稳定且超过 6 个 | 容易变成"什么都能塞"的默认模板 |
| 顶栏 + 文档流 | 顶部横向导航，单栏 60–75 字符测度 | 阅读型、说明型、设置页、需要安静的界面 | 不适合高频切换对象的操作 |
| 工具条 + 工作台 | 顶部工具条 + 多面板网格，面板可独立滚动 | 指标看板、需要同时看多个视图 | 面板一多就失焦，要有主视图 |
| 主列表 + 详情 | 左索引列表，中间主视图，右侧详情 | 在条目间反复切换（运行、工单、客户） | 窄屏必须退化，详情不能挤主视图 |

对比页面见 [结构菜单](../assets/ui-lab/structures.html)：四种骨架共用同一份数据与组件，可叠加切换主题，用来验证"换结构不改数据、换皮肤不改排列"。选择规则偏向操作距离：**要反复点选的对象放近处，要读的正文给足横向空间**。

## 五、风格条目（参考方向，不是白名单）

"气质 → 落地要点"的速查。本地已实现的皮肤见 [themes/](../themes/README.md)，未实现的用查询词去 `ui-ux-pro-max` 取完整 token：

```bash
python3 ~/.agents/skills/ui-ux-pro-max/scripts/search.py "<查询词>" --domain style   # 或 --design-system
```

| 风格 | 气质 | 适合 | 需权衡 | 落地要点 | 本地 / 查询词 |
| --- | --- | --- | --- | --- | --- |
| 文档纸面 | 暖白、安静、可信 | 文档、说明、阅读型产品 | 密集数据需无衬线读数与清楚层级 | 暖白画布、暖灰文字、单一陶土强调、标题衬线、发丝线代替阴影 | [paper-cream](../themes/paper-cream.md) |
| 极简中性 | 克制、组件统一 | 工作台、设置、管理界面 | 需要强品牌感的营销页 | 中性主操作、精细边界、统一控件比例 | [shadcn-neutral](../themes/shadcn-neutral.md) |
| 现代 SaaS | 明亮、效率 | 仪表盘、分析台 | 阅读型长文 | 浅色表面 + 亮蓝主操作、状态色鲜明、数据可视化优先 | [modern-saas](../themes/modern-saas.md) |
| 观测站 / 仪器 | 精确、工程感 | 科研看板、实验监控 | 消费级产品 | 网格画布、铭牌线条、读数用大字号 | [bespoke](../themes/bespoke.md) |
| 预览卡片 | 轻、有呼吸 | 内容以图片/预览为主 | 密集表格 | 大圆角白块、阴影分层、无边界 | [bento](../themes/bento.md) |
| 瑞士网格 | 理性、正式 | 文档型、机构、极简专业 | 亲和型消费产品 | 数学栅格、发丝线、直角、单一强色 | [swiss](../themes/swiss.md) |
| 玻璃 | 通透、层次 | 浮层、导航、轻量面板 | 长列表与表格 | 平色玻璃（去渐变）、清楚文字层次、实色兜底 | [aurora-glass](../themes/aurora-glass.md) |
| 柔和粉彩 | 亲和、低压力 | 表单、设置、轻量工具 | 合规与金融严肃场景 | 降亮、圆润字形、柔和阴影 | [soft-ui](../themes/soft-ui.md) |
| 编辑杂志 | 有观点、可读 | 内容站、长文、品牌故事 | 高频操作台 | 非对称栅格、衬线正文、大图与引言 | `editorial grid magazine` |
| 布鲁塔 | 强硬、直接 | 作品集、实验性产品、开发者工具 | 政务与金融 | 直角、粗描边、无过渡、单色高对比 | `brutalism` / `neo brutalism` |
| 暗色电影 | 沉浸、聚焦 | 媒体、专业工具、监控 | 白天户外、打印 | 不用纯黑、分层表面、光晕克制、缓动明确 | `modern dark cinema` |
| 终端 / CLI | 极客、数据流 | 开发者工具、链上产品 | 面向大众的产品 | 等宽字体 + 绿/琥珀、等宽网格、状态行 | `terminal cli` |
| 自然暖砂 | 手作、可持续 | 生活方式、健康、内容 | 高密度后台 | 陶土/砂米/橄榄、低饱和、纹理grain 克制 | `nature distilled` |
| 复古胶片 | 怀旧、温暖 | 影像、音乐、品牌故事 | 严肃 B2B | 褪色暖调、颗粒、光斑，注意性能与可读性 | `vintage analog retro film` |
| 学院羊皮纸 | 书卷、庄重 | 阅读工具、文化社区 | 现代科技感产品 | 深木色 + 羊皮纸 + 黄铜、衬线标题、拱形与暗角 | `academia scholarly` |
| 超极简大字号 | 宣言式、强对比 | 品牌首页、展览、作品集 | 表单与数据表 | 极大字号、极限留白、单一强调色、几乎无装饰 | `exaggerated minimalism` |

三条选择纪律：① 产品保持一致识别度（见 [themes/README.md](../themes/README.md)）；② 控件与表面共享语言，动效节奏/密度按区块目的变化；③ 新方向先做关键区块对比，不为选了一个风格名就直接全量铺开。

## 六、选定之后

1. 落到 token（CSS 变量/主题文件），沿用产品识别度，不散落硬编码色值。
2. 工作组件用同数据检查状态与可读性；章节展示检查停顿帧、阅读顺序与节奏。统一主题不要求统一构图。
3. 实际点击、键盘、滚动、小屏与减少动态效果都能用；看截图与实际节奏，不只看数值。
4. 按 [evolution.md](../evolution.md) 记录认可范围；一页认可不代表全部组件/设备，候选不写成 Confirmed。
5. 需要复杂叙事与视觉 QA 时读 `huashu-design` 的 storyboard、animation 与 critique 参考；需要生产页面实现时保留现有工程约束。
