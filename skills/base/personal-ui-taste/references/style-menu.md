# 风格菜单：想不出风格时，怎么选出一个方向

2026-10-08 建立。用途：解决"框架太死板、想不出更好的形式"。**先定结构，再定皮肤，最后才是配色细节**；三个决定都不要凭直觉硬猜。

## 一、先说话，再选库

| 情况 | 做法 |
| --- | --- |
| 用户给了品牌、设计系统、截图、参考站点 | 从那里长出来。不要套菜单，也不要把参考改造成别的风格 |
| 什么都没有，需求模糊（"做个好看的"） | 给 **三个真实差异**的方向让用户挑：跨维度（材质 / 密度 / 排版 / 导航位置），不是同一套配色的三种色相 |
| 已有界面要改造 | 先审再改：按 [design-philosophy.md](design-philosophy.md) §6 走一遍，只改有问题的维度 |

每个方向都说清四件事：一句气质、一张参考画面（或本地主题名）、关键 tokens、**做过头会变成什么**（反例）。选定后不再反复问；换方向是新任务。

## 二、色彩推导协议（三步）

不要临场发明颜色。任何风格落地前先走这三步：

1. **采样**：从真实参考物取色——品牌物料、实物照片、现成截图。屏幕纯色、凭感觉调的色相是最容易露馅的地方。
2. **收敛**：统一灰阶与色温，限制装饰色。纸面方向可降饱和；shadcn 式产品可用纯白和中性文字；数据/状态保持可区分性。不把“低饱和”或“禁止纯白”当普遍高级公式。
3. **论证**：每个颜色回答"它代表什么角色"：画布 / 表面 / 边界 / 文字 / 强调 / 状态 / 数据系列。说不出角色就不要这个颜色。

同色相在不同语境里含义不同，取色前先确认语境（红：警示 / 喜庆 / 品牌；绿：成功 / 生态 / 金融下跌；白：干净 / 丧葬 …）。要更多风格与色彩参考时读 `huashu-design` 的 `references/design-styles.md`（网页/PPT/信息图各 20 种，含色彩推导协议与文化语境速查）。

## 三、结构菜单：同一份内容，四种骨架

选主题之前先选骨架。**内容决定骨架，不是先摆卡片再想内容**：

| 骨架 | 长什么样 | 适合 | 风险 |
| --- | --- | --- | --- |
| 侧栏 + 主栏 | 左导航常驻，右侧单栏内容 | 多页面工作台、导航项稳定且超过 6 个 | 容易变成"什么都能塞"的默认模板 |
| 顶栏 + 文档流 | 顶部横向导航，单栏 60–75 字符测度 | 阅读型、说明型、设置页、需要安静的界面 | 不适合高频切换对象的操作 |
| 工具条 + 工作台 | 顶部工具条 + 多面板网格，面板可独立滚动 | 指标看板、需要同时看多个视图 | 面板一多就失焦，要有主视图 |
| 主列表 + 详情 | 左索引列表，中间主视图，右侧详情 | 在条目间反复切换（运行、工单、客户） | 窄屏必须退化，详情不能挤主视图 |

对比页面见 [结构菜单](../assets/ui-lab/structures.html)：四种骨架共用同一份数据与组件，可叠加切换主题，用来验证"换结构不改数据、换皮肤不改排列"。选择规则偏向操作距离：**要反复点选的对象放近处，要读的正文给足横向空间**。

## 四、风格条目（精选；全量去查外部 skill）

"气质 → 落地要点"的速查。本地已实现的皮肤见 [themes/](../themes/README.md)，未实现的用查询词去 `ui-ux-pro-max` 取完整 token：

```bash
python3 ~/.agents/skills/ui-ux-pro-max/scripts/search.py "<查询词>" --domain style   # 或 --design-system
```

| 风格 | 气质 | 适合 | 避免 | 落地要点 | 本地 / 查询词 |
| --- | --- | --- | --- | --- | --- |
| 文档纸面 | 暖白、安静、可信 | 文档、说明、阅读型产品 | 数据密集盘 | 暖白画布、暖灰文字、单一陶土强调、标题衬线、发丝线代替阴影 | [paper-cream](../themes/paper-cream.md) |
| 极简中性 | 克制、组件统一 | 工作台、设置、管理界面 | 需要强品牌感的营销页 | 中性主操作、精细边界、统一控件比例 | [shadcn-neutral](../themes/shadcn-neutral.md) |
| 现代 SaaS | 明亮、效率 | 仪表盘、分析台 | 阅读型长文 | 浅色表面 + 亮蓝主操作、状态色鲜明、数据可视化优先 | [modern-saas](../themes/modern-saas.md) |
| 观测站 / 仪器 | 精确、工程感 | 科研看板、实验监控 | 消费级产品 | 网格画布、铭牌线条、读数用大字号 | [bespoke](../themes/bespoke.md) |
| 预览卡片 | 轻、有呼吸 | 内容以图片/预览为主 | 密集表格 | 大圆角白块、阴影分层、无边界 | [bento](../themes/bento.md) |
| 瑞士网格 | 理性、正式 | 文档型、机构、极简专业 | 亲和型消费产品 | 数学栅格、发丝线、直角、单一强色 | [swiss](../themes/swiss.md) |
| 玻璃 | 通透、层次 | 浮层、导航、轻量面板 | 长列表与表格 | 平色玻璃（去渐变）、清楚文字层次、实色兜底 | [aurora-glass](../themes/aurora-glass.md) |
| 柔和粉彩 | 亲和、低压力 | 表单、设置、轻量工具 | 合规与金融严肃场景 | 降亮、圆润字形、柔和阴影 | [soft-ui](../themes/soft-ui.md) |
| 编辑杂志 | 有观点、可读 | 内容站、长文、品牌故事 | 高频操作台 | 非对称栅格、衬线正文、大图与引言 | `editorial grid magazine` |
| 布鲁塔 | 强硬、直接 | 作品集、实验性产品、开发者工具 | 政务与金融 | 直角、粗描边、无过渡、单色高对比 | `brutalism` / `neo brutalism` |
| 暗色电影 | 沉浸、聚焦 | 媒体、专业工具、监控 | 白天户外、打印 | 不用纯黑、分层表面、光晕克制、缓动明确 | `modern dark cinema` |
| 终端 / CLI | 极客、数据流 | 开发者工具、链上产品 | 面向大众的产品 | 等宽字体 + 绿/琥珀、等宽网格、状态行 | `terminal cli` |
| 自然暖砂 | 手作、可持续 | 生活方式、健康、内容 | 高密度后台 | 陶土/砂米/橄榄、低饱和、纹理grain 克制 | `nature distilled` |
| 复古胶片 | 怀旧、温暖 | 影像、音乐、品牌故事 | 严肃 B2B | 褪色暖调、颗粒、光斑，注意性能与可读性 | `vintage analog retro film` |
| 学院羊皮纸 | 书卷、庄重 | 阅读工具、文化社区 | 现代科技感产品 | 深木色 + 羊皮纸 + 黄铜、衬线标题、拱形与暗角 | `academia scholarly` |
| 超极简大字号 | 宣言式、强对比 | 品牌首页、展览、作品集 | 表单与数据表 | 极大字号、极限留白、单一强调色、几乎无装饰 | `exaggerated minimalism` |

三条选择纪律：① 同一产品只用一套风格（见 [themes/README.md](../themes/README.md)）；② 风格是系统，不是装饰——选定后圆角、阴影、动效节奏都要跟着走；③ 冷门风格先做一屏对比再全量铺开。

## 五、选定之后

1. 落到 **token**（CSS 变量/主题文件），不要散落硬编码色值；一个产品一套。
2. 用**同一骨架 + 同一数据**复验一遍：换皮肤不该改变信息组织，也不该破坏状态可辨性。
3. 按 [evolution.md](../evolution.md) 记录"认可到什么范围"：一个页面的认可不等于整套组件、深色配对、窄屏都已确认。
4. 需要动效叙事、缓动曲线与视觉 QA 时，用 `huashu-design` skill（`references/animation-best-practices.md`、`scripts/verify.py`）。
