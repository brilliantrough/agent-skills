# 美术风格层 · 皮肤库与选择规则

2026-10-04 经对比实验建立，随后纳入用户明确偏爱的 shadcn 风格（evolution.md v1.18.0）。本目录回答"界面**看起来**怎样"；SKILL.md 与 scenarios/ 回答"内容**怎样组织**"。骨架与皮肤均可演进；主题之间共享组件做法，不必共享同一种主色。

## 用法

1. 先从内容与任务推导形式，再讨论视觉方向。已有主题或用户指定时沿用其识别度，仍可提出更好构图；方向未定时给差异化方案与推荐，不只把下表当风格选择题。shadcn-neutral 优先考虑现代工作台/设置，非所有新页面的自动默认。
2. 主题内 tokens 是**起始参考值**，按项目已有设计体系就近适配；不把 hex 当验收标准。可运行参考见 [UI lab](../assets/ui-lab/README.md)，其中 `themes/<主题>.css` 提供实际变量与控件覆盖。
3. 同一产品保持统一的视觉语言与语义 tokens；章节可以换构图、密度和主角，不必每块套同一张卡。
4. 用户明确否决的处理按下方「反感清单」的范围执行；中性灰不等于灰蒙，轻量按钮不等于无法识别的按钮。

## 落地方式与切换器

- 主题一律 **token 化**落地：组件消费语义变量。换色通常只改变量表；圆角、密度、材质与动效按主题适配，不能保证全部换肤只改一个文件。
- **默认只落地所选的一套主题，不做页面内切换器。** 共用组件能降低新增主题成本；每套仍需检查状态、文字、图表与浮层，不能只验变量表。
- 三种情况才做运行时切换器：① 选择期对比（[随包实验室](../assets/ui-lab/index.html)：一份结构 + base.css 契约 + 每主题一份变量 CSS）；② 页面面向多用户；③ 明暗双主题等明确需求。
- 开工询问不为此加问题：用户没提就默认单主题。

## 跨主题通用美术偏好（2026-10-04 确认）

- **参考优先于粗略形容**：用户早期“可能喜欢亮蓝”不是唯一审美；明确喜欢的实际作品可修正旧描述，保留各主题的适用范围。
- **字体要管控**：明确中英文字体配对、层级、字重与行高；数字保持 `tabular-nums`。沿用项目交付方案，或按需用 Fontsource 自托管，见下方共用指引。
- **强调随主题**：亮蓝、中性色和其他已选色调均可成立；主操作、选中、状态与数据系列各有语义，不让一枚 accent 承担所有角色。
- **层次要清楚**：用排版、间距、表面和细边界建立秩序；中性灰与轻阴影可以精致。卡片是否可点击决定 hover 提示，静态摘要无需假装成按钮。
- **状态灯带**：保留红黄绿信号与就近说明，颜色清楚鲜明；modern-saas 可用放大/辉光，shadcn-neutral 可用实色与轻微反馈。
- **导航与搜索（T14）**：偏好圆润边界、同组等宽导航与整行命中区；具体比例见 shadcn-neutral 的个人变体。常驻导航不再用贴文字的小号药丸；不把大面板也做胶囊，swiss 等明确主题的直角取舍仍保留。
- **交互反馈**：hover、focus、pressed、selected、disabled 都可辨；克制的底色/边界变化即可。波纹、下沉、辉光由主题选择，遵循 `prefers-reduced-motion`。

## 各主题共同吸收的做法

落地读 [视觉做法与参考源](../references/visual-craft.md)：shadcn 的组件状态与比例、Radix 的用途色阶、Stats 的摘要层级、Simple Icons 的品牌识别、Fontsource 的字体交付、Badges 的短标签表达。

| 主题 | 精修落点 |
| --- | --- |
| shadcn-neutral | 中性主操作、轻边界、统一控件比例；数据与状态按需用彩色 |
| modern-saas | 亮蓝主色保留，补齐按钮层级与菜单状态，统一字体和图标尺度 |
| bespoke | 仪器读数与刻度槽保留；摘要带单位/范围，图例与提示共用语义色 |
| bento | 保留预览卡片；标题、元信息、操作层级统一，只有可操作卡片强化 hover |
| swiss | 保留网格与直角；借字号、字重、对齐和品牌图标的统一尺度，不强加圆角 |
| aurora-glass | 保留平色玻璃；借色阶与文字层级，复验透明表面叠加后的对比度 |
| soft-ui | 保留圆润质感；借字体字重、状态层级与边界，避免粉彩和阴影糊成一片 |
| paper-cream | 衬线仅衬托展示标题，控件与数据无衬线；发丝线代替阴影、陶土单点强调；状态色整体降饱和，避免与陶土撞色相 |

这些是改进方向；已有主题不统一改成 shadcn。具体融合在项目里目验后再记录细节。

## 新主题入库流程

1. 用户明确认可的外部作品，可按“参考风格 Confirmed”加入选择；写清来源，具体 tokens 与新实现仍待目验。无需把已认可的方向重新降为 Candidate。
2. Agent 自提风格先做同元素对比页，用户认可前记 Candidate；可使用本地对比实验室，通用记录随 themes/ 分发。
3. 实际呈现后按 evolution.md 记录认可范围、否决项、调整项；不将风格认可扩大成每个组件、明暗模式或依赖选型均已确认。
