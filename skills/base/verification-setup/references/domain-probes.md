# 领域风险探针与反伪绿灯清单

扫描阶段按项目命中的形态读取对应小节，作为蓝图初筛清单；只选与当前项目真实入口和风险匹配的项，不按清单机械套全套。

## 1. 通用软件工程（CLI / API / Web / 库与数据脚本）

| 维度 | 重点探针（扫描什么） | 优先落点 |
| --- | --- | --- |
| 入口与参数契约 | CLI 退出码、子命令帮助、非法参数拒绝、stdout／stderr 洁净度；API 请求校验、状态码、错误结构 | L1 类型／schema + L2 进程／HTTP 契约测试 |
| 数据与状态防损 | 写入原子性、重复执行幂等、并发冲突、部分失败回滚、已有用户数据不丢失 | L2 隔离临时目录／内存或临时库实跑 |
| 信任与安全边界 | 未信任文件路径、目录穿越、符号链接越界、权限位（如凭据 `0600`）、敏感值泄露 | L1 静态敏感扫描 + L2 负面反例测试 |
| 异步与错误处理 | 失败传播不静默吞错、超时／取消后资源与子进程回收、重试上限与退避 | L1 linter（空捕获／未处理 Promise）+ L2 故障注入 |

## 2. PyTorch / 模型训练、量化与评测脚本

面向科研与算法工程，先保证**小成本、秒级确定性防错**，不把昂贵的全量 GPU 训练／评测塞进日常快门禁。

- **L1 静态与配置检查**：依赖导入、配置字段合法性、数据路径与设备参数解析、严禁硬编码个人绝对路径或泄露凭据；实验脚本不得反向破坏公共核心模块接口。
- **L2 确定性烟测（CPU 或单卡极小合成输入，秒级）**：
  - **数值与形状契约**：前向／反向传播无 `NaN`/`Inf`、输出 `shape`/`dtype`/`device` 与预期一致、关键参数确实产生非零梯度；
  - **算子／量化／迁移等价**：新实现或优化核与参考实现在固定随机种子下的误差在声明容差内（`atol`/`rtol`），覆盖边界长度与非对齐 batch／seq；
  - **数据与状态防损**：checkpoint 保存→重载恢复后状态与输出一致、数据划分防泄露（train／val／test 样本独立性检查）。
- **L3 Evaluation（按需独立入口，不进默认快门禁）**：
  - 区分研发调优集与独立留出验收集；记录模型、数据集 split、seed、精度格式、硬件与框架版本口径；
  - 固定小规模代表性子集做快速回归对比，全量 benchmark 估算耗时配合 `eval-time-estimate`，量化误差分析衔接 `kb-8bit-quantization`。

## 3. 插件 / 多宿主配置与安装脚本

- **L1 静态与闭包检查**：脚本语法（`bash -n`、`py_compile`、`shellcheck`）、模板 JSON／YAML／TOML 合法性、入口直接引用的资产闭包与入库核对、公开模板零真实私密值、共用函数防分叉。
- **L2 离线隔离行为验证（独立临时 `HOME`／`XDG_*`）**：
  - **私密保护与合并**：真实敏感键、自定义条目与占位符在多次更新后保留，空值槽位可补齐；
  - **幂等与备份**：二次运行零无效改写、不重复生成备份、用户本地漂移先备份再覆盖（或按策略保留）；
  - **符号链接与权限边界**：区分根链接、中间父链接与叶子链接，明确哪些拒绝写穿、哪些按契约写穿并保留原链接；
  - **失败保旧与事务回滚**：源码缺失、下载失败、配置解析失败或中途报错时保留旧可用版本，不留下半成品；
  - **零污染约束**：所有安装／配置测试必须显式覆盖 `HOME` 与宿主目录环境变量，且不得联网或修改共享后台 worker。
- **真实宿主验收边界**：离线模拟只能证明脚本与配置生成逻辑，真实宿主进程加载、插件挂载、快捷键与权限交互必须单列为独立宿主验收项（缺宿主或隔离 runtime 时显式 `SKIP HOST`）。

## 4. 桌面应用 / Electron / TUI 交互界面

- **L1 静态与边界检查**：跨进程导入边界（如 `main`/`renderer`/`contracts` 依赖方向）、类型检查、构建产物与资源引用完整。
- **L2 可编程驱动验证**：
  - **纯逻辑下沉验证**：状态机、布局计算、快捷键解析、IPC 消息编解码与渲染去重优先抽离做毫秒级无头单测；
  - **真实表面驱动**：Web／Electron 优先走 Playwright 或宿主可控预览接口；TUI 优先走 PTY／tmux 捕获真实输出与退出状态；
  - **就绪判定而非硬编码延时**：驱动前检测明确的就绪信号（端口响应、DOM locator、提示符出现），避免用固定 `sleep` 猜启动时间；
  - **高发交互回归**：焦点切换、剪贴板／复制、滚轮与鼠标命中、窗口缩放、会话切换与异常退出后终端恢复。
- **L3 视觉与观感检查（按需）**：关键页面或状态留存截图基线或视觉审查清单；区分“脚本注入输入通过”与“真实终端／物理桌面实操验收”。

## 5. LLM / Agent / Prompt 与 RAG 评测（Evaluation 专项）

当项目包含 Agent 工作流、Prompt、检索增强或生成式流水线时，按以下四要素建立轻量可演化 Eval：

1. **分层样例集**：区分冒烟集（5–15 条覆盖核心主路径与必拦反例，改动后常跑）与扩展回归集（历史踩坑、边界输入、对抗拒答例，发版或大改前跑）；每次修完真实线上／实机失误，沉淀 1 条最小反例进集。
2. **可复现采集**：固定模型名、推理档／温度、系统提示词版本、工具集与输入夹具，落盘原始轨迹（输入、工具调用序列、输出、耗时／token），避免靠口头印象对比。
3. **确定性优先的评分**：
   - 先用硬规则判结构与行为（JSON／schema 合法、是否调了正确工具、是否遵守禁区与拒绝条件、引用路径是否真实存在）；
   - 仅对开放质量维度使用明确分项 rubric（LLM-as-judge 或人工抽检），并与人工标注对齐校准，不迷信单一总分。
4. **基线与诚实统计**：单次跑通不等于稳定可用；记录对比基线与允许退化阈值，明确区分确定性失败与采样波动。

## 反伪绿灯自检清单

验收任何新搭建的检查或回归时，逐条排除以下五种伪通过：

1. **退出 0 却未执行断言**：脚本因缺依赖、空测试目录、吞掉异常或未输出明确 `PASS` 而静默返回 0；应改为缺前置显式 `SKIP`、零匹配直接 `FAIL`。
2. **Mock 自洽**：测试只验证了自己造的桩函数被调用，没有走到当前生产实现路径或真实状态变更。
3. **从未证明能红**：新写的静态规则、正则或回归测试从未在违规样例或旧缺陷上实际跑失败过。
4. **隐式依赖本机 live 状态**：测试读到了开发者的真实 `HOME`、本机配置、全局缓存或仓外软链，换一台干净机器即失效或反向污染本机。
5. **用慢速／脆弱信号阻塞快循环**：把固定 `sleep`、外网请求或全量重评测绑进每次改动的默认快检查，导致 Agent 和开发者绕开整个门禁。
