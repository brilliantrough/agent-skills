# Unslop：本次改动的去冗余

实现完成后、交付前执行一次：把本次改动里没有真实职责的 AI 产物删掉，其余事实与行为原样保留。标准档开发任务自动调用；轻量档默认不跑，用户显式要求时照跑。独立复核仍按档位、风险和项目规则判断。它和 `quick-do`／`steady-do`／`plan-brief` 的复杂度分工正交。

不做整仓整理，不判断功能是否做对，也不替代用户验收。

| 情况 | 走哪里 |
| --- | --- |
| 本次改动的代码、注释、文字去冗余 | 本 skill |
| 授权范围内的项目结构、记忆或历史报告整理 | 显式调用 `consolidator`，由其委派 `consolidation-reviewer` |
| 标准档或强制的独立功能复核 | `verification` 与 `verification-reviewer` |
| 只读讨论、纯调研、纯文字成稿 | 不启动本步骤；文字仍按 `readable-docs` |

## 1. 先定基线与范围

- 记录起点：当前 `HEAD`、已暂存与未暂存改动、用户原有未完成工作。差异不等于本次工作，基线外的东西不顺手清理。
- 范围默认是本次授权改动；用户可显式限定到文件、目录或模块。没有授权就不扩到全仓。
- 完成判据：能说出本次改动的文件清单、哪些是本次产出、哪些是必须原样保留的他人工作。
- 实现完成后单独查看授权范围的最终差异；写代码时已顺手清理也要复查。Git 项目检查本次相关的已暂存与未暂存差异，并直接读未跟踪新文件；非 Git 项目直接复读改动。没有冗余就说明本次检查无需删改，不另写报告。

## 2. 清理

代码按 Ponytail 取舍，复用 `trust-pyramid` 的注释与补丁配方判断根因：

- 投机防御：可信内部调用里重复的存在性／类型／空值检查、没有真实消费者的兼容回退、按现有控制流不可达的分支。
- 多余结构：透传包装、一次性抽象、没人使用的参数、配置和扩展点；Agent 为自证而建的 manifest、hash 或核对清单。
- 注释：复述代码、记录开发过程、替绕路实现辩护的说明删掉；契约、外部约束、算法引用、许可证和 `shortcut: <限制>, <何时升级>` 保留。
- 文字：README、说明和交付文本按 `readable-docs` 短检查处理，删模板腔、空泛铺垫、重复背景和装饰性格式，事实、条件、范围和指令强度不变。
- 同一语义在多处维护时合并到一处，其余改成对该处的引用。

## 3. 这些不删

真实信任边界的输入校验、数据防损、防篡改、实际故障的错误处理、许可证与来源声明、用户资产、必要行为，以及有触发条件的 `shortcut:`。

与任务核心相关、违背代价高的关键纪律，在不同决策点的刻意重复不算冗余；要删的是与任务无关的细节和无行为价值的同义复述。

## 4. 语义保持与纠错边界

- 纯清理不改变行为、输出、接口和错误语义。为通过检查或图省事而顺手改逻辑，不属于本步骤。
- 清理中发现必须修的行为问题，在任务授权内到根因处修一次，并在交付里单列这项行为变化，不把它写成清理。
- 范围外的 bug 只报告位置、现象和影响，不顺手修，也不扩大成本。

完成判据：本次清理没有改变应保持的行为；若同时修复了问题，行为变化已单列。

## 5. 交接验证

本步骤只清理，验证责任仍在主 Agent：清理后重跑受影响的静态检查、最小真实路径和相关回归；改到行为的，按 `verification` 重验受影响部分。

- 不新增 Reviewer，也不改现有路由：功能复核按 `verification` 的档位与风险触发，整理审查只在用户显式调用 `consolidator` 后出现。
- 与功能复核同时进行时，先完成本步骤并冻结范围，再把清理后的最终版本交给复核；复核后又有改动，只补验受影响部分。
- 范围外的重要发现交给用户决定，不在本步骤内处理。

## 停止条件

本次授权范围内的冗余已清完，剩余内容都能说明真实职责，必要时已单列行为变化和范围外发现，即结束。不为“可能还有”继续扫全仓，不把删行数或文件数当成果。
