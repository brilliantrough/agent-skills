# Goal Run：高密度对齐，验证先行，无人值守跑通

本技能是面向重型目标的薄编排合同：把本套件现有能力串成同一条流水线，不自造外置工作流引擎、DAG 调度器或独立状态机。前段利用短窗口一次问透并先校准验证尺子，用户一键启动后连续跑完所有里程碑，**禁止中途停下请示**，**禁止放松出口谓词宣布胜利**。

## 定位与触发门禁

仅在用户显式调用 `goal-run`，或明确要求“短时高密度对齐 + 验证先行 + 拉满预算无人值守跑完”时启用；普通任务不自动升格到这里。

| 场景 | 使用入口 | 边界 |
| --- | --- | --- |
| 从零启动重型目标，需要发散调研、高密度对齐与一键无人值守跑通 | `goal-run` | 含前段全量对齐与 M0 验证基座先行 |
| 日常任务做到一半需要挂机或“跑到绿” | [`steady-do`](../steady-do/SKILL.md) | 沿用其第 6 节可判定谓词、原生唤醒与 `decisions.tsv` |
| 只需要出方案或人工跨会话交接 | [`plan-brief`](../plan-brief/SKILL.md) | 不强绑定发散并发与无人值守预算 |
| T3 Code 中跨 Gemini 与 OpenCode 双核协作 | [`t3-plan-execute`](../t3-plan-execute/SKILL.md) | 可作为 `goal-run` 阶段 3 的执行拓扑 |
| 过程止损与主线聚焦 | [`goal-first`](../goal-first/SKILL.md) | 全程约束投入方向，不代替执行流 |

## 阶段 0：解构问题与只读发散探索（自动执行）

收到需求后先自行做足功课，不把能查清的事实抛给用户。

1. **读现场与纪律**：读取项目根 `AGENTS.md`（含 `user-discipline` 强制约束）、项目画像与用户原始诉求。
2. **问题建模**：调用 [`problem-framing`](../problem-framing/SKILL.md) 与 [`goal-first`](../goal-first/SKILL.md) 剥离局部动作，写清期望终态、已知约束、关键未知与最怕自欺欺人的假绿灯反例。
3. **只读发散探索（3-5 路并发）**：调用 [`multi-agent`](../multi-agent/SKILL.md) 的只读发散探索模式，按任务相关性并发派出 3-5 路只读子代理（按需派出、不凑数；每路只给单轴问题、停止条件和返回证据）：
   - **代码与运行现场**：架构、真实调用链、解释器与依赖版本、已有测试/评测入口及复用点。
   - **记忆与过往操作**：召回 `claude-mem`、Magic Context 与项目 `docs/` 中的历史决策、踩坑与用户惯例。
   - **外部方案与先例**：联网检索成熟方案、开源实现对照与常见陷阱。
   - **反例与失败面**：隐藏耦合、边界条件、安全/性能风险，以及“看似通过却没真解决”的反例。
   - **意外替代路线（可选）**：提出 1-2 个跳出直觉拆解的备选方案。
4. **阶段 0 完成判据**：主会话核实并收敛出极简《调研与候选快照》，只保留会改变决策的事实、反例与候选路线。

## 阶段 1：短时高密度对齐

假定用户仅有 15-20 分钟集中交流窗口。把 [`grilling`](../grilling/SKILL.md) 的分轮前沿追问与 [`verification-setup`](../verification-setup/SKILL.md) 的验证蓝图对齐合并为**一套统一访谈**，绝不拆成需求与验证两轮重复发问。

- **前沿打包提问**：每轮抛出当前前置已清的全部未决决策，编号并给出推荐答案与简短利弊；已查清的事实绝不发问，已定事项跳过。
- **必须收口的 5 类决策**：
  1. **目标、非目标与方案拍板**：结合阶段 0 发散快照与备选路线定下边界。
  2. **验证与评价尺子先行（`verification-setup`）**：定死最终**可判定出口谓词**（确定性正反例 + 必要定量/质量指标）、静态快拦截、离线自跑与真机/人工验收边界，明确 `M0` 先落尺子。
  3. **规约拆解与执行拓扑**：定清共享接口契约、里程碑依赖、高预算下可并行的独立写分片（允许 3-5 路，仍严守互斥写集或 worktree 隔离）与执行载体（本会话 / 原生 `/goal` / T3 双核）。
  4. **自治授权边界与熔断默认表**（供用户一键确认或微调）：
     - 默认预授权自动执行：工作区内改代码与文档、建/跑静态检查与测试评测、装局部项目依赖、经本轮总授权后建隔离 worktree、本地 checkpoint commit。
     - 默认须显式确认或留到收尾人工处理：`git push`、创建/合并 PR、改外部或生产环境、不可逆删除、全局系统包安装、触碰密钥与隐私配置。
     - 质量档与熔断：默认**标准档**（[`unslop-changes`](../unslop-changes/SKILL.md) + 独立复核，不因无人值守降格）；同一阻塞换假设连续 **3 轮** 无实质进展即熔断并保留现场。
  5. **交付终点**：本地验证完结 / 到 PR / 需保留的证据形式。
- **阶段 1 完成判据**：设计树前沿清空，5 类决策均无静默假设。

## 阶段 2：蓝图落盘与一键启动门禁（Hard Gate）

按 [`plan-brief`](../plan-brief/SKILL.md) 落盘计划文档（默认 `docs/plans/YYYY-MM-DD-<slug>.md`），必须写全四块硬合同：

1. **可判定出口谓词**：每条绑定可执行命令或可观察产物；执行期禁止放宽谓词。
2. **自治授权表与 3 轮熔断条件**：写清预授权动作、绝对禁区与熔断规则。
3. **里程碑清单**：**`M0` 固定为验证与反馈基础设施先行**（最小 codebase 骨架 + 静态快拦截 + 统一验证/评测入口 + 红灯证明或基线校准）；`M1…Mn` 为共享契约驱动的实现与串联集成；`M_final` 为 Unslop + 全量出口谓词复跑 + 独立复核。
4. **执行拓扑与勾选进度表**：标明并发分片写集、隔离方式与依赖顺序，配合本地不入库 `decisions.tsv` 记录关键决策与检查点。

**硬门禁**：停在计划就绪，未获用户显式一键启动前严禁修改项目业务代码。向用户输出浓缩总览、计划路径，并按当前宿主提供一键发车入口：

- **支持原生 `/goal` 的宿主**（Codex、Claude Code、Antigravity、OpenCode V2）：附一段可直接发送的原生 `/goal` 启动指令（内含计划路径、全部出口谓词、阶段 3 禁早停与 3 轮熔断规则），借助宿主 Stop Hook 物理防早停，并提醒核对自动审批模式（如 `auto`）。
- **无原生 `/goal` 的宿主**（Pi、DSH 等）：用户回复“启动”后直接在本会话进入阶段 3，长耗时作业配合 `later` 或宿主后台唤醒。
- **T3 Code 组合拓扑**：阶段 0-2 在 T3 主代理完成；启动后二选一：
  - **形态 A（主代理直跑）**：在当前 T3 主代理内开 3-5 路原生 subagent 推进（可配原生 `/goal`）。
  - **形态 B（T3 双核委派）**：按 [`t3-plan-execute`](../t3-plan-execute/SKILL.md) 用 `delegate_task` 委派 OpenCode (GPT) 跑通 `M0…M_final`（或由用户在新 OpenCode 线程用原生 `/goal` 接棒该计划），完成后按阶段 3 回到主会话做只读结构/品味/观感审查。

## 阶段 3：全速无人值守执行与收口门禁

1. **先过 `M0`（兵马未动，粮草先行）**：按 [`verification-setup`](../verification-setup/SKILL.md) 落地最小骨架、静态快拦截与验证/评测入口，实跑确认最小红灯证明或可复现基线校准；`M0` 未校准严禁进入 `M1`。
2. **禁止中途停下请示**：完成 `M1`、`M2` 后严禁停下来汇报进度或问“要不要继续 `M3`/`M4`/`M5`”。计划内可回退的局部实现自主决策并简记 `decisions.tsv`，不发提问；新发现不影响交付且无须改协议时只在收尾简记。
3. **仅 3 类硬边界允许中断交回**：
   - 撞到自治授权表中的未授权禁区（如必须执行未批准的不可逆或外部操作）。
   - 新证据推翻计划核心前提，涉及目标、接口契约或交付范围的产品级改判。
   - 同一阻塞换不同假设连续 **3 轮** 无实质进展（触发熔断，保留现场、日志与已跑证据）。
4. **高并发执行与长耗时续接**：
   - 主执行代理掌控共享契约、串联集成与里程碑状态勾选；每推进一个单元立即验绿再往下走，不把检查堆到末尾。
   - 独立写分片按 [`multi-agent`](../multi-agent/SKILL.md) 可并行 3-5 路：先锁共享契约，严守互斥写集或 worktree 隔离，共享端口、GPU 与数据库单独隔离；未推进试探直接丢弃（Ponytail）。
   - 长耗时后台任务走宿主原生后台唤醒或 `later`（同 [`steady-do`](../steady-do/SKILL.md) 第 6 节），严禁 `sleep` 或轮询。
5. **T3 双核委派要点**：采用 `t3-plan-execute` 时，派单 brief 必须自包含传递计划路径、全部出口谓词、自治授权表、3 轮熔断与末级 `multi-agent` 并发授权（3-5 路只读发散或获授权互斥分片，末级禁再向下委派）。
6. **最终收口门禁**：
   - 全部里程碑绿灯后，执行 [`unslop-changes`](../unslop-changes/SKILL.md) 清理本次授权差异。
   - 复跑全量出口谓词、静态检查与最小真实路径，并按 [`verification`](../verification/SKILL.md) 将最小可重复回归接入项目现有入口。
   - 调用原生 `verification-reviewer` 独立复核（未注册时如实披露并用只读子代理辅助核查，不冒充已注册角色）；不通过则自动闭环修复重验，直到全部谓词通过或触发 3 轮熔断。
   - 在 T3 双核模式下，OpenCode 收口后回到 Antigravity 完成只读结构/品味/观感审查与最多 1 轮定点返工。
7. **一页交付报告**：只交付与结论相关的硬证据——逐条出口谓词实测输出与验证层级（静态 / 隔离 / 真实宿主 / 待人工实机）、改动清单、未验证项与 SKIP、触发熔断或阻塞的保留现场。部分完成绝不标 `done`。

## 演化

经验演化型：每次实机运行后，记录阶段 1 遗漏的高频决策、3-5 路发散调研的信噪比及 3 轮熔断命中情况，以最小修改回流本技能。
