# 中文去模板化完整检查

用于显式润色、humanize、去 AI 味、去模板化，或模板问题密集的长文。先执行 `../SKILL.md` 的事实边界和成稿流程，再逐项检查本目录。日常短回复不必逐条展示检查过程。

这些是编辑线索，不是词语黑名单或作者身份判据。命中后必须确认表达确实空泛、重复、歧义或与文体不符；没有问题的地方保持原样。优先级固定：事实与确定程度 → 用户范围与文体 → 作者声音 → 表达偏好。

规则参考并改写自 `blader/humanizer` v4.0.0 与 `op7418/Humanizer-zh` 2026-09-23 版，来源和许可见 [THIRD_PARTY_NOTICES](../THIRD_PARTY_NOTICES.md)。

## A. 铺垫代替陈述

| 检查点 | 怎么处理 | 什么时候保留 |
| --- | --- | --- |
| 假对比：“不是／不仅是 X，而是／更是 Y” | 删除没有信息的否定半句，直接写 Y | 否定纠正真实误解，或两半都有独立信息 |
| 单句收尾、戏剧性碎片 | 删除重复感叹、解释例子的尾巴，合并同义碎片 | 短句提供新事实、真实态度或必要强调 |
| 格言与伪深度 | 回到具体判断，不把“协作是效率的语言”当论据 | 被引用的格言，或确实帮助理解的比喻 |
| 起跑式铺垫 | 删除“接下来深入看看”“下面是你需要知道的” | 确实影响理解的导航或阅读前提 |
| 与假想敌辩论 | 删除“不要误会”“有人可能认为”等无对象辩护 | 真实反对意见、限制条件和读者实际会比较的方案 |

## B. 公式化节奏

| 检查点 | 怎么处理 | 什么时候保留 |
| --- | --- | --- |
| 强凑三点、三连例子 | 按独立信息决定项数，合并重复例子 | 三项分别承担不同含义或约束 |
| 句式开头复读 | 合并动作或改变句子组织 | 有意排比、时间顺序或主体不同 |
| 机械变化句长 | 按理解需要重写，不为“自然”交替长短句 | 节奏本身服务重点和语气 |
| 破折号当万能连接 | 明确解释、转折、因果或停顿关系 | 中文破折号承担真实功能，符合作者样本 |
| 限定词堆叠 | 合并重复的不确定性表达 | 不同限定分别约束证据、范围、条件或风险 |
| 生造复合词与连接号 | 使用已有定义或直接写动作 | 固定术语、必要英文连字符 |

## C. 拔高、宣传与借权威

| 检查点 | 怎么处理 | 什么时候保留 |
| --- | --- | --- |
| 空泛高频词：“赋能、闭环、至关重要” | 换成实际动作、关系或影响 | 有具体技术含义，如“闭环反馈” |
| 意义拔高：“标志着新时代” | 删除没有独立内容的评价 | 真实计划、首次事件、明确作者判断 |
| 模糊关联：“与……有关” | 已知关系就写清角色、因果或用途 | 关系确实未知；保留未知，不猜 |
| 句尾补充式拔高：“彰显了……” | 删除重复赞美 | 句尾有真实原因、目的、结果或影响 |
| 宣传语：“梦想天堂、革命性、无缝” | 写实际特征，保留主观评价的身份 | 主观评价不改成测试结论或客观排名 |
| 借权威：“专家认为、行业公认” | 保留真实来源及其主张，删除空的背书 | 来源未知时保留归因和局限，不编造机构 |
| 回避“是／有”：“作为、设有、承载着” | 更直接时改为“是／有”或直接动词 | 数量、比较、可能性、范围会因此改变时不缩 |

## D. 公式化排版

| 检查点 | 怎么处理 | 什么时候保留 |
| --- | --- | --- |
| 粗体当装饰、每项都有粗体标签 | 删除无检索价值的强调，必要时改为连续句 | 警告、关键操作、长文定位所需重点 |
| 装饰性标题、emoji、箭头、分隔线 | 标题写实际内容，删无功能装饰 | 箭头承载流程，标题或锚点受文件契约保护 |
| 列表／表格泛滥 | 能一句说清就不拆点；非比较内容不硬塞表格 | 独立步骤、条件和同维度对比确实需要结构 |
| 引号与标点机械替换 | 按中文正文和目标格式统一 | 代码、JSON、原文引语、用户指定样式 |

## E. 聊天、草稿与自证残留

| 检查点 | 怎么处理 | 什么时候保留 |
| --- | --- | --- |
| 客服腔：“好问题、希望有帮助、要不要我继续” | 独立文本中删除，只留实际内容 | 邮件、书信、客服场景中的真实礼貌功能 |
| 重复免责与猜测填充 | 删除重复铺垫，写清具体资料缺口 | 真实不确定性、时效范围、风险和验证边界 |
| 首句复读标题 | 删除没有独立信息的复述 | 首句提供条件、定义、范围或数据 |
| 编辑过程残留：“这一段刚补充” | 删除正文中的改写自述 | 变更日志、迁移指南需要前后差异 |
| 工具流水和审计式自证 | 只留结论、必要证据与真实未验证项 | 用户要求过程、审计契约或复现步骤时 |

## F. 中文表达补充

| 检查点 | 怎么处理 | 什么时候保留 |
| --- | --- | --- |
| 层叠的“的” | 重排长定语，保留修饰关系 | 当前结构没有歧义且容易理解 |
| “进行＋动词” | 冗余时换直接动词 | “正在、计划、完成”等状态会改变时保留对应表达 |
| 被字句堆叠 | 施事明确且主动更清楚时调整 | 施事未知、不重要或文体需要被动 |
| 四字词排比 | 删除同义堆叠，改为具体动作或特征 | 四字节奏自然、每项含义独立 |
| “随着……的发展”式背景 | 删除没有独立信息的宏大背景 | 真实趋势、时间背景或因果关系 |
| 套话收尾：“拭目以待、期待更多可能” | 删除祝愿和重复赞美 | 有内容的总结、真实情绪或下一行动 |

## G. 读者、上下文与作者声音

| 检查点 | 怎么处理 | 什么时候保留 |
| --- | --- | --- |
| 重复解释读者已知背景 | 先给决定或结论，只保留会改变判断的新事实 | 独立文档没有共享上下文，必须自解释 |
| 答案最后、证明过程在前 | 把答案前移；工具细节和验证过程只留必要部分 | 用户要求推导、审计、复现或完整诊断 |
| 所有文体都改成聊天语气 | 技术文本保持准确，学术／商务保持正式，随笔保留个性 | 用户明确要求改变文体 |
| 作者样本机械套用 | 只借鉴表达习惯，不搬经历、数据、立场 | 样本和目标文本本来就在陈述同一事实 |
| 每句都改、每篇都缩短 | 已清楚的内容不改；必要解释不删 | 原文已经自然、完整且适合读者 |

## 高命中示例

### 技术回复：先回答，不重建上下文

**改写前：**

> 你问的是为什么升级后仍保留旧密钥。为了回答这个问题，我们需要先了解配置合并的整体机制，然后再分析敏感键的处理。这个过程涉及多个方面。值得注意的是，这不仅是一个配置问题，更是安全问题。merge_cfg 对 apiKey 和 baseURL 等敏感键保留本机值，非敏感共有键随模板更新，本地独有键不删除。经过上述分析可以看出，保留旧密钥是为了避免覆盖本机凭据。

**改写后：**

> `merge_cfg` 遇到 `apiKey`、`baseURL` 等敏感键时保留本机值，避免升级覆盖凭据；非敏感共有键随模板更新，本地独有键不删除。

### 中文说明：去套话，不删状态

**改写前：**

> 这次更新充分彰显了团队的创新精神。它不仅新增 CSV 导出、全文搜索和批量重命名，更开启了高效协作的新篇章。离线编辑计划在下一版推出，目前尚未完成测试。总而言之，让我们拭目以待。

**改写后：**

> 这次更新新增 CSV 导出、全文搜索和批量重命名。离线编辑计划在下一版推出，目前尚未完成测试。

### 不确定性：只删重复，不改证据强度

**改写前：**

> 在目前掌握的有限资料下，可以看出该问题被认为可能与内存泄漏有关。虽然具体细节比较有限，但原因尚未确认。

**改写后：**

> 该问题被认为可能与内存泄漏有关，但原因尚未确认。

### 作者声音：不借润色改变立场

**改写前：**

> 我对全面取消人工校对有些拿不准。自动提示确实省事，但它在这次演示里把一句玩笑当成了承诺。我还不准备因此否定这个工具。

**改写后：**

> 自动提示确实省事，但这次演示把一句玩笑当成了承诺，所以我对全面取消人工校对仍有保留，还不准备因此否定这个工具。

## 最后一次通读

- 新增的具体信息都能在原文或用户材料中找到；没有就撤回。
- 否定、比较、范围、时间、条件、归因、规范强度和作者立场没有变化。
- 每项列举、表格行和独立论据仍有存在理由；没有为了避模式而删信息。
- 答案和下一行动足够早；没有重复背景、空泛收尾或不必要的自我证明。
- 文体和作者声音保持；已经清楚的地方没有被强改。
- 代码、链接目标、显式 ID、YAML、数据和受保护结构完整。

不用自评分、字数下降或“AI 味消失”代替语义核对。单次改写通过不代表跨模型、跨文体稳定有效。
