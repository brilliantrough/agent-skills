# 主线优先：每一步买到必要进展或有效信息

**用户目标与已约定验收，高于新发现的吸引力、技术趣味和实现的漂亮程度。能做、容易做、有意思，都不单独构成现在做的理由。**

**收益最大，拒绝内耗。** 本套件明确接受用少量可快速补回的返工换长期低维护：即使偶尔因小细节过度删除而返工，也不为避免这点返工而保留一摊“可能有用”的文件、分支、抽象或校验产物。后面真需要就按当时需求最小补上；现在没有真实用途的过程产物就删。不要把犹豫当审慎，不要把保留成本排除在效率计算之外。

**关键纪律要有意复现。** 与任务核心相关、违背代价高的规则，要在套件／仓库的不同阶段、决策点和失败模式前反复强调；这不是冗余，而是防止高代价失守。精简重复内容时，只清理与任务无关的细节、无行为价值的同义复述和已失效表达。

本 skill 管投入与方向；`ponytail` 管最小完整实现，实验／开发 skills 管具体步骤。沿用现有任务记录，不再建立一套管理流程。

只修改自维护套件。`grilling`、`diagnosing-bugs` 等第三方技能保留上游方法与更新能力；自有入口说明调用目标、阶段和适用范围，求同存异，不为统一风格给第三方正文打补丁。

## 1. 锚定问题与目标，不限定唯一方案

科研主线可以是问题或认识目标，多条求解路线可并行贡献；竞争、互补、依赖或分条件适用都合理，不要求最终只留一个赢家。Ponytail 减少无效投入与重复表达，不削减有价值的路线或证据覆盖；路线现状由 `project-profile`／`save-mem` 维护，不另建台账。

在现有 todo、任务卡或短任务的一句理解中明确：

- **交付**：用户最终需要什么可观察的结果；哪些语义与验收不能缩水？
- **当前未知／阻塞**：什么最可能使这次工作失败，或改变下一步选择？
- **下一步**：最小但足以推进交付、排除解释或验证关键假设的动作。
- **收口**：本步做到哪里就够；可选探索的成本预算及暂停条件。

阶段切换、出现意外结果、准备扩大范围或成本超预期时回看。简单改动一句即可；不在每个工具调用前填表或向用户报批。

## 2. 用最短的方法论循环推进

借波利亚的“理解—计划—执行—回顾”维持闭环，而不是增加仪式：

| 动作 | 执行要求 | 完成判据 |
|---|---|---|
| 理解 | 区分事实、假设、未知和用户选择；先查已有证据 | 能说清问题与验收，不重复询问已定事项 |
| 计划 | 找关键不确定性或待证主张；比较代理、矩阵等证据路径 | 明确可获得的认识／证据、覆盖与成本；不强求每格立即改变决策 |
| 执行 | 做一个有意义的完整单元；先验证代表性路径，再扩大 | 得到真实实现或有效证据，失败也可追溯 |
| 回顾 | 比较预测与实际，更新判断并决定继续／修订／收口 | 下一步由证据决定，不由兴奋、惯性或沉没成本决定 |

复杂问题从目标拆到必要子问题；每个子问题须能解释如何支撑父目标。借金字塔式表达先讲结论、再给支撑与下一步；不为结构对称硬凑维度或材料。

## 3. 新工作先说明认识、验证或决策价值

适用于新增实验、调研、优化、抽象和扩大验证；已确定的必要实现步骤无需逐条辩护。

> 为解决未知 U，做动作 A，观察证据 E；结果 X 会使我做 B，结果 Y 会使我做 C。成本大致为 K，观察到 S 即结束。

这是可判别实验的写法，不是所有研究的强制模板。探索矩阵可以先说明要认识的参数响应、交互或权衡，不必预知结果，也不必给每个格子编造一个即时决策。

- 若各种结果都不改变行动、结论可信度或明确的探索性认识目标，默认不做。
- 复用已有证据，并按有效性选择单点检查、真实对象代理或整模实验矩阵；代理不是必经关卡，不能为省事删掉关键依赖或必要配置覆盖。
- 先解决可能推翻整条路径的假设，不先打磨容易完成的局部细节。
- 有意义的阴性结果也是进展：它排除解释、关闭分支或界定适用范围。无需保证每次实验“赢”，也不准事后把无目的乱试包装成研究。
- 探索性研究可以没有确定预测，但须有明确问题、学习目标和有界预算；不为形式完整编造假设。
- 时间、算力、实现／维护成本和用户注意力一起考虑；使用粗估即可，不另造评分模型。
- 按实际对象、执行方式和整批成本选步骤：小数据集参数矩阵也属预研，真实评测批量运行前仍需轻量代码审视／校验；不把“预研”当低成本保证，也不把所有预研限定为抽取张量。

### 实验矩阵本身可以就是主线

| 目的 | 矩阵的价值 |
|---|---|
| 探索方向 | 暂不清楚下一步时，观察参数响应、方案差异、交互和性能权衡，形成新假设 |
| 解释效果 | 用消融与组合对照区分贡献、退步和适用条件；代理看不清时获取更直接的整模证据 |
| 论文论证 | 覆盖约定模型、配置、预算、基线及必要重复，展示帕累托前沿与稳健性，支撑可信主张 |

- 这些矩阵与 `goal-first` 一致。完整矩阵是否必要由研究问题和证据覆盖决定，不由“格子多”判断；不以实验数量最少为目标。
- 以矩阵整体说明问题、因素／范围、指标、比较公平性和预算；正式论证不能因早期某个点漂亮就省掉必要覆盖。
- 防止的是没有认识／论证目的、已有充分同口径答案却机械补点或无边界扩张；有信息价值的曲线和覆盖不是镀金。

## 4. 意外发现不能自动接管任务

1. 先问：它是否影响当前结果的正确性、关键假设、既定验收或真正的交付阻塞？
2. **影响**：按主线依赖调查，做最小区别性检查；原方案若失效，说明证据并调整必要步骤。涉及目标／协议／预算的实质变化再与用户对齐。
3. **不影响**：返回主线。确有以后价值才短记证据与重开条件，不自动增加实验、重构或长期待办。

不得因“发现很有趣”静默扩展研究对象、搜索空间、交付范围或性能目标。抓住根因属于必要工作；追逐无关机理不是。

## 5. 陷阱识别与立即动作

| 陷阱 | 自查信号 | 动作 |
|---|---|---|
| 过早优化 | 还不知道是否在关键路径，就准备改快 | 先定向测量；已有充分证据则直接行动 |
| 局部优化 | 只证明一个指标更漂亮，与总任务无关 | 回到端到端目标／科学问题，检查实际贡献 |
| 过度设计 | 为想象中的模型、插件、用例建通用层 | 只覆盖当前明确需求，保留最小可替换边界 |
| 自行车棚效应 | 在名称、样式、小参数上反复讨论，关键未知没动 | 采用现有约定或够用方案，先解阻塞 |
| 镀金 | 验收已过，为外观添功能／补点或抠无关微小收益 | 完成交付；论文主张所需的曲线与矩阵覆盖仍属必要工作 |
| 沉没成本／无界探索 | 理由变成“已经做这么久，再试一次” | 要求新的可判别假设或证据，否则停该分支 |
| 方法论膨胀 | 整理流程、报告、工具比解决问题更费时 | 缩成现有记录中的几行，删重复步骤 |

## 6. 明确何时停，什么不能省

- 验收满足、证据足够后收口；完整实验矩阵可属于必要验收，不一概强求也不一概排除。不要将无需的极致调优或所有潜在改进加入交付。
- 同样输入／前提下已回答的问题直接复用；重复测量须服务噪声判断、变更回归或明确的科学置信需求。
- 可选分支预算耗尽或连续尝试没有新增可判别信息时暂停；不自动换一个热点继续耗时。
- **停止的是无价值扩展，不是用户要求。** 必要正确性、数值语义、约定覆盖与真实验收不能削减；主线受阻就继续解决必要阻塞或明确报告原因，不能借止损假装完成。
- 未知与失败按证据陈述；计划、计时器、启动成功、进程结束、文件存在都不能代替完成证明。
- 完成后只沉淀能避免复犯的最小经验。具体模型、路径和状态进项目记录，可复用规则进入对应 skill；不把这次任务扩成工具平台。

## 演化

经验演化型：发现实际偏航时，优先改诱发行为的条款；公共原则在本 skill 维护，各入口只保留短指引。新增规则须说明减少了哪种浪费，不堆叠口号或强制流程。
