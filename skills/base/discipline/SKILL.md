# Discipline：让用户纪律进入指令层

**记录不是完成，激活才是。** 把用户明确指定的规则变成当前任务与后续阶段必须检查的约束，不只保存一条可供将来检索的记忆。纪律块不是第四套记忆，不存项目现状、一般经验或历史流水。

## 1. 只在用户显式触发时升格

- 用户明确调用 `discipline`，或说“记入纪律／修改纪律／撤销纪律”时才使用。普通“记住”“以后注意”“保存一下”仍走 `save-mem`；不得自行把所有“必须”“禁止”提升为长期纪律。
- 默认保存为当前项目的长期纪律；用户明确说“仅本轮／仅这次”时，只在当前任务激活，不写长期块。
- 沿用用户给出的规则，不改写成弱建议。只有适用范围、执行动作或冲突处理仍不明确，且不同理解会改变行为时，才集中追问。
- 用户最新的明确修改或撤销为准。与现有纪律冲突而用户未明确要求替换时，停止相关编辑并指出冲突，不静默覆盖。
- 显式触发只授权维护纪律块及当前任务计划，不授权修改无关配置、覆盖私密值或执行不可逆回滚。

## 2. 先作用于当前任务，再落盘

1. **暂停相关动作**：读取当前 todo／计划和已有纪律块，确定哪些正在进行的动作受此规则约束；不得等到任务结束才处理。
2. **明确约束**：用“适用／必须／禁止／失守处理”复述。保留用户指定的条件与强度，不写成长篇宣言。
3. **检查冲突**：核对当前计划及本次任务已完成的相关工作。已经违反或即将违反时，立即停止相关操作，指出规则与具体偏差；未经授权不做不可逆补救。
4. **激活执行**：把适用的短纪律提示加入当前 todo／计划和阶段验收。编辑文件不等于宿主已经刷新系统提示；写入后必须重读并在当前会话持续执行，不能等下次会话才生效。

## 3. 长期纪律写入 AGENTS 顶部受管块

在项目根 `AGENTS.md` 的项目自有内容之前维护**唯一**受管块。不要另建 `DISCIPLINE.md`、`docs/discipline/` 或第二个 AGENTS 副本。

```markdown
<!-- user-discipline:start -->
## 用户纪律：强制约束，不是背景记忆

### D-001 规则名称
- 适用：什么任务、阶段或操作前触发。
- 必须：必须完成的动作与可观察的完成判据。
- 禁止：不得采用的做法。
- 失守处理：立即停止相关操作，说明偏差并纠正；不得仅补记一条教训后继续。
<!-- user-discipline:end -->
```

- 没有 AGENTS 或受管块时，按上式创建；保留块外全部内容与顺序。发现多个块、标记不完整或块外内容可能受损时，停止并让用户确认，不整文件覆盖。
- 每条规则使用稳定编号与具体名称。规则正文短、硬、可检查；失败代价不显而易见时，在“适用”或“禁止”中用一句具体事实说明，不堆砌“极其重要”。
- 只保存现行纪律。同主题变化原位更新，不按日期追加新版；撤销时删除对应现行规则。需要保留变更理由或历史时，另交 `save-mem` 写入 decisions／journal，纪律块不承担历史档案。
- 只有用户明确要求才能新增、修改、降调或撤销。Agent 不得因规则看似重复、过时、影响效率或与画像／记忆不一致而自行改动；发现实质冲突时报告。
- 不写入密钥、令牌或私密配置值。本机私有规则沿用项目已有的私有指令边界，不进入公共模板。

## 4. 可选预置：Ponytail 全生命周期纪律

用户明确说“用 discipline 启用 Ponytail 预置纪律”时，将以下规则写入受管块。安装或刷新套件时不得自动写入；预置文本只在本 skill 维护，项目中的副本是用户启用后的现行指令，不被 setup 自动覆盖。

```markdown
### D-001 Ponytail 全生命周期纪律
- 适用：规划、开发、保存、阶段审查，以及每次显式调用 consolidator 的小范围整理。
- 必须：采用最小完整实现；保存即原位维护；审查同时检查误删真实保护和“该删未删”；整理时直接清除授权范围内的临时囤积、伪安全产物及重复失效表达，将持续价值并入现有资产，接受可快速补回的小返工。
- 禁止：不因“以后可能有用”或“无法证明绝对安全”保留杂物；不新增投机防御、第二维护源、工具流水或 hash/diff/manifest 台账；不把关键纪律的刻意重复当冗余；不自动全仓整理，不牺牲真实保护、必要证据和未闭合风险。
- 失守处理：立即停止相关编辑、保存或整理，指出具体偏差并在授权范围内修正；不得只交建议、另造清理清单或等待下一轮。
```

- `D-001` 已被占用时使用下一个未用编号，保留规则名称。用户已有同主题手写纪律时先展示冲突，不重复插入或静默替换。
- 启用后按第 2 节立即激活，不顺便开展全仓整理。以后每次显式调用 `consolidator` 时按此口径直接小修小减，但未给范围仍需确认，真实验证与独立审查仍保留。
- 详细方法仍归 `goal-first`、`save-mem`、`readable-docs`、`consolidator`；本预置只提升跨阶段动作与禁止退路，不替代这些技能，也不允许 consolidator 自行改写纪律块。

## 5. 在关键阶段反复检查，不靠一次阅读记住

- **规划与开工**：先检查适用纪律，再确定方案和动作；`quick-do`、`steady-do`、`plan-brief` 都必须带上相关约束。
- **执行与阶段转换**：方案改变、范围扩大或新证据出现时重新检查。需要在不同决策点重复同一短句，这是刻意强化，不是冗余。
- **审查与交付**：逐条核对本次适用的纪律，报告遵守情况或具体违反；不得用“已写入 AGENTS／已保存记忆”代替行为验收。
- **记忆与画像**：`project-profile` 只登记入口；`save-mem` 可保存理由、背景和历史，但不得用普通记忆替代或降格现行纪律。
- **整理**：`consolidator` 与 reviewer 将现行纪律块视为用户指定的受保护指令，不作为重复文本、旧规则或冗杂内容清理。
- **宿主加载**：新会话核对 AGENTS 是否被实际注入；未自动加载时使用该宿主已有的原生项目指令入口接入，不新增注册框架。当前会话仍按第 2 节立即激活并主动重读。

## 6. 完成判据与边界

只有同时满足以下条件才可说“纪律已记录并激活”：

- 当前任务的相关计划与动作已按新规则调整，已有冲突已报告。
- 长期规则已写入唯一受管块，块外内容未变；仅本轮规则明确未持久化。
- 当前 todo／计划及阶段验收已带上适用约束，后续能检查具体行为。
- 修改、撤销或冲突均按用户明确意图处理，没有自行降调。

本 skill 是高显著度行为协议，不是权限系统或沙箱。真正需要技术强制的不可逆、高风险操作，另行使用宿主原生权限边界；不得为了普通偏好新增硬编码拦截。
