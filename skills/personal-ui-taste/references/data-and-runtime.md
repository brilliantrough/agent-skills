# 数据与运行约定：按需要选读

这些是分析看板容易误判的边界。先复用实际项目定义，只处理本次任务涉及的部分。

## 1. 指标能怎样合并

| 指标 | 合并所需条件 | 常见误用 |
| --- | --- | --- |
| 字节、金额、事件数 | 互不重叠的事实，单位与范围一致 | 重复关联、同一事件同时落入多个子组后直接相加 |
| 平均值、成功率、占比 | 保留分子分母或权重，重新计算 | 平均各组平均值；把各自分母不同的百分比相加 |
| 峰值、分位数 | 同步原始序列或可证明支持目标口径的聚合结构 | 相加各对象历史峰值，冒充组合同时峰值 |
| 去重对象数 | 身份集合或适用的去重算法 | 相加各组独立去重数，忽略跨组重叠 |
| 余额、库存、活跃量 | 明确时点与跨对象规则 | 把每分钟状态相加成期间总量 |

现有数据不足以得出目标指标时，隐藏、标记不可得或说明新口径生效点。不要给旧数字换单位来伪造历史。

## 2. 从快照采集时

- 先辨认累计计数、区间增量、瞬时值和完整事件流；轮询快照不自动等于完整流水。
- 累计差分的速率除以真实经过时长；更新基线前完成增量计算。相邻成功样本间隔过长、计数重置或身份改变，按数据源语义重建基线。
- 初次启动不把全部旧累计塞入新时间桶；跨缺测差额是否能归因要有依据，不能机械补成一次大峰值。
- 采集频率、提交频率、历史粒度、页面刷新是四个不同选择；分别依据漏采容忍度、丢失窗口、查询任务和资源开销确定。
- 来源接口看不到的短生命周期记录或结束尾差，不能通过界面补算；标明观察范围。“连接数”“任务数”“请求数”不可互换。
- 实例总量与分组和对比时，必须对齐入口、类别、时段和计数含义；无法归因的差额不强行分摊。

## 3. 时间范围与数据质量

- 时间查询统一边界约定；采用 `[start,end)` 时，相邻窗口不重复计入端点。内部时间与展示时区职责清楚。
- “截至现在”与显式历史终点区分；若只存分钟数据，说明非整分钟范围怎样对齐。
- 滚动一小时依据真实时间，不能依据“最近60条非空记录”。计算查询起点的窗口时按需读取起点之前的数据。
- 无活动但采集正常可以为0；缺测为未知。时间轴补齐后保留缺测间断，降采样和覆盖条压缩也不能抽掉缺口。
- 部分覆盖值可以展示为已观测下限；进行中桶单独标记。阈值未触发，不证明缺测期间没有发生高消耗。

## 4. 持久化与历史身份

| 需求证据 | 优先考虑 |
| --- | --- |
| 只浏览一次静态文件 | 现有文件与前端查询即可，不新增常驻采集 |
| 已有完整数据库或指标API | 复用数据入口，避免第二份事实来源 |
| 单机连续采集、需跨重启保留 | 评估已有或嵌入式数据库、明确数据目录与提交策略 |
| 多实例写入、共享权限和运维 | 评估现有共享数据服务，不强套单机文件方案 |

- 事实、维度标签、覆盖状态、用户设置按其职责保存；表和文件数量由实际查询需要决定。
- 提交成功后才移除待写数据；失败状态可见，缓冲有界，恢复规则明确。重启不能覆盖已经提交的同一时间桶。
- 留存清理必须考虑活动缓存、未提交缓冲和外键引用。可选字典清理没有完整引用策略时，暂不清理比复用失效ID可靠。
- 分类更新是否影响历史显示要明确。当前分类可以重算映射，但不应修改原始字节、事件数等事实。
- 用真实行数增长、维度组合数和查询耗时判断容量；设备少不等于组合少，不预先保证一个固定文件大小。
- 备份遵循实际数据库的一致性方式；不要默认复制一个正在写入的主文件就是完整备份。

## 5. 运行方式是交付的一部分

仅当产品要求后台持续运行或重启恢复时，落实以下事项：

- 查当前运行环境、启动方式、数据路径、进程身份、端口与访问边界，再选择现有进程管理方式。
- 将程序、持久数据、临时数据和凭据位置区分；复用项目权限惯例，避免为了启动而放宽无关目录。
- 数据目录和运行身份必须在重启后仍可用；健康信息区分采样成功、提交成功、缓存陈旧。
- 页面关闭不影响后台采集；进程重启后设置和历史仍在，当前连接/任务按约定重新建基线。
- 升级时核对实际运行副本与构建物；只启停任务授权的服务。历史口径变更先保留原值和生效时间，不静默改写。
- 文档写已验证的服务、数据库与恢复命令。一个本机HTTP 200不能替代其他客户端访问或长期稳定性证据。

## 6. 小规模反例比更多装饰有用

按变化选少量可解释输入，复用现有检查或一次实际操作：

- 同一对象在两个资源上访问同一服务：验证合并后金额/字节正确、明细仍保留差别。
- 不同对象通过同一资源访问不同服务：验证换分组入口不改变总量。
- 稀疏时间记录相隔超过窗口：验证不会被凑成“滚动小时”。
- 先有用量、后无状态、再正常零流量：验证缺测与0不混淆。
- 字典仍被缓冲引用时触发清理：验证没有错归或悬空引用。

只将示例用于隔离数据或获得授权的验证路径；完成当前检查后，不为假设的未来需求扩建测试系统。
