# 美术风格层 · 皮肤库与选择规则

2026-10-04 经对比实验验收建立（evolution.md v1.15.0）。本目录回答"界面**看起来**怎样"；SKILL.md 与 scenarios/ 回答"内容**怎样组织**"。两层独立：先按场景定结构，再从本目录选皮肤。

## 用法

1. 平地起高楼（新页面/新产品）开工时，先按下方「风格选择询问模板」让用户选皮肤；用户已指明风格、或任务只是明确的局部改动时跳过询问，直接用指定款或场景默认（SKILL.md 工作方式 · 询问分寸）。均未指定时退回 SKILL.md「视觉落地基线」的兜底值。
2. 主题内 tokens 是**起始参考值**，按项目已有设计体系就近适配；不把 hex 当验收标准。
3. 同一产品内只用一套主题；跨页一致性优先于单页出彩。
4. 用户明确否决的处理记录在「反感清单」，任何主题都不得带回。

## 跨主题通用美术偏好（2026-10-04 确认）

- **字体要管控**：工作型界面默认引 Inter 类现代无衬线（Google Fonts 或项目已有），不再无管控落系统栈；数字保持 `tabular-nums`。用户明确认为受控字体全面优于旧基线。
- **蓝色要亮**：主强调用现代亮蓝（`#2e6bf0` / `#0b84f3` / `#2547f4` 家族），旧基线 `#3b63dc` 偏灰仅作兜底。
- **卡片不灰蒙**：卡片采用所选主题的处理（圆角、阴影、悬浮反馈），不再用旧基线的朴素灰卡。
- **状态灯带**：颜色亮而鲜艳（modern-saas 处理为标杆），hover 放大并带同色系辉光；各主题灯带均向此看齐。
- **交互特效**：hover/focus 150–240ms；导航活跃项用指示条/渐变等明确形态；按钮有点击反馈（波纹/下沉/辉光其一）。仍遵循 `prefers-reduced-motion`。

## 新主题入库流程

1. 与现有主题同元素对比页并列展示（对比实验室：开发机 `agent-skills/.ui-style-lab`，本地忽略不随仓库分发；tokens 以本目录 md 为可移植记录）。
2. 用户视觉验收后按 evolution.md 记录：认可范围、否决项、调整项。
3. 只有 agent 觉得好看而未经用户目验的，记 Candidate，不进默认选择。
