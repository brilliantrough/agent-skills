# 交互模式与踩坑记录

主要场景 S01：浅色信息密集界面；模式 7 同样适用于 S02。按组件选读；这里只记录视觉与交互模式，具体 DOM、框架和代码跟随目标界面。

## 1. 多系列图表：目标命中与持久聚焦

**经历的问题**：整列透明矩形接收所有鼠标事件，用户实际悬浮/点击某个色块却只能高亮整柱。

**适用范围**：下表中的“色块”也指折线或数据点；验证指标与训练 Loss 等多系列曲线同样适用，包括不显示圆点的密集线段。这是默认交付要求，不等用户再次提出。轴向 tooltip 可以展示多个系列，但必须明确突出实际命中的那一个。

| 状态 | 图形 | Tooltip / 图例 |
| --- | --- | --- |
| 空闲 | 全部正常 | 隐藏提示 |
| 悬浮色块 | 单块突出，其余淡化；可轻微缩放/阴影 | 对应条目突出，其余淡化 |
| 点击色块 | 锁定此块，离开鼠标仍保留焦点 | 同步使用选中条目；离开图形可收起提示 |
| 点击另一块 | 切换选中目标 | 同步切换，不能保留旧项 |
| 再点同块 / Esc / 点击图外 | 清除锁定和淡化 | 清除聚焦提示 |

实施要点：

- 焦点身份使用稳定的 `(chart, bucket/time, series key)`；不要只保存会随排序/过滤漂移的数组下标。
- SVG 色块自己接收事件，整列空白命中层位于色块后方；图表库使用对应的 segment/dataPoint 事件。
- 交互区、柱块和 tooltip 从同一焦点状态渲染，不能各自猜测选中对象。
- 数据刷新时能匹配稳定 ID 就保留；筛选/维度变化使对象消失就清除。提示不能展示上一批数据。
- 锁定后浏览其他柱子，需明确是“保持锁定”还是“临时悬浮后恢复”，图与提示始终一致；已确认实现采用前者。
- 点击聚焦可以兼容原有“明细按时段过滤”，但不要悄悄添加新的业务筛选含义。
- **实际踩坑**：点击处理里重绘 DOM 后，冒泡到 document 时旧节点已脱离树，`target.closest()` 误判为图外，立即清掉刚选中的块。使用事件原始路径 `event.composedPath()` 判断，或用框架等价方案保留原始事件归属。
- 键盘支持：左右时间桶，上下堆叠项，Enter/Space 选中，Esc 解除；可用 roving tabindex，避免几千个 Tab 停靠点。
- 灰化 opacity 约 0.18–0.3 只是视觉起点；聚焦条目文字保持可读，并提供正常状态恢复。

折线实现与验收：

- 不假定图表库的 `emphasis` 会同步修改自定义 tooltip。提示框每次重建和焦点变化时，都按同一稳定系列 ID 更新条目样式；避免新框仍显示旧焦点。
- 线段事件与圆点事件的字段可能不同：例如 ECharts 的线段命中可能只有 `seriesIndex`，没有 `seriesId/dataIndex`。用当前图表系列表解析稳定 ID，不让缺失 ID 导致所有条目变淡；不要把数组下标持久保存为身份。
- 多系列轴指示器的默认“全部高亮”不能覆盖目标焦点。锁定后浏览其他系列，图形与提示均保持锁定系列；图例原有隐藏/显示功能须保留。
- **交付前必须真实操作**：分别命中一个圆点和一段无圆点折线，确认图形、tooltip、图例只有对应系列突出；再验证切换目标、移开恢复、点击锁定、重复点击/Esc/图外解除、筛选后清理旧焦点。至少检查普通位置和最右侧提示。
- 仅调用 `showTip`、看到提示框弹出或静态截图正确，都不能证明联动通过。用真实鼠标/触摸事件验证，并检查对应条目身份及其他条目确实变淡；沿用现有浏览器检查，不为此新增测试框架。

## 2. 右侧 Tooltip：测量后翻转，不把名称挤窄

**常见问题**：最新数据在最右侧，提示框使用残余空间自动收缩；`max-width` 和强制断词又使条目名称折行。用户恰好最常查看此处。

步骤：

1. 先渲染完整内容，以 `width: max-content` 或组件库等价设置取得自然宽度，限制为视口可用宽度。
2. 在不受上次 `left` 剩余空间影响的位置测量，例如视口原点；不可对 `display:none` 的元素测量。
3. 右侧放不下 → 放到锚点左边；下方放不下 → 上翻。
4. 最后夹取到视口边距，默认约 12px，锚点间隔约 16px。
5. 桌面常规名称保持单行；视口真的窄于内容时才允许合理换行、最大高度/滚动或更适合手机的详情面板。

```text
left = x + gap + width <= viewportWidth - margin
       ? x + gap : x - gap - width
top  = y + gap + height <= viewportHeight - margin
       ? y + gap : y - gap - height
最后将 left/top 夹取到可视范围
```

- 数值不要折行；名称与数值拉开间距。不要用省略号掩盖用户正想看的完整名称。
- 鼠标和键盘焦点共用定位逻辑；滚动、resize 和数据变更后重定位或收起。
- 如果放在 transformed 容器里，先解决 fixed 坐标系和 overflow 裁剪；优先已有 portal/overlay 机制。
- 很长内容需要滚动时，浮层必须可交互，或提供点击详情；`pointer-events:none` 的纯悬浮框不能承担不可达的滚动内容。
- 验证：最右非空桶、长名称（例如 `Collection A · Extended Edition`）、9+条目、顶部/底部边缘、手机，及先在左侧出现再移到右侧的情况。

### 2.1 密集图表：详情挡线、条目溢出与画布不足

**触发症状**：“信息框太大”“挡住曲线，点不到另一条”“条目看不全，也滚不动”“并排画布太小”。先复现用户指出的多系列筛选；少量曲线截图不能代表这个问题已解决。

| 原因/场景 | 优先考虑的处理 |
| --- | --- |
| 两图并排使线段、标签和命中空间拥挤 | 改成各占内容区一整行，适当增高；保留已认可的侧栏和筛选。不要靠缩小文字容纳更多内容 |
| 大浮层覆盖目标，移动鼠标又使浮层追随 | 先扩大可用画布，再在目标附近偏移、自动翻转/夹取浮层；保留就近查看的视觉联系 |
| 条目超出可视高度，需要逐项查看 | 浮层限高、允许进入滚动，标题保留 epoch/时间/step；切换系列时让高亮条目进入可视区域，手动滚动时不抢回位置 |
| 已改为图下固定详情，用户觉得不直观 | 恢复悬浮详情，保留已改善的画布；消除遮挡不能以牺牲用户偏爱的就近阅读为代价 |
| 内容少，只是右边贴边 | 保留轻量 tooltip，按 §2 翻转和夹取；不必强制增加固定面板 |

**关键取舍**：`pointer-events:none` 可以避免浮层截获点击，却无法让用户滚动浮层；仅加 `overflow:auto` 也不代表可操作。浮层必须可进入，可用短暂离开延时跨过锚点间隙；进入后保持位置、内容和焦点，避免追着鼠标移动或立刻关闭。

悬浮详情实施要点：

- 悬浮更新当前数据，进入详情后保留最后有效读数，不能因鼠标离开线段立即清空；点击锁定仍按 §1 工作。在详情里点击或滚动不能误判为“点击图外”解除锁定。
- 继续同步曲线、详情条目和图例的焦点，详情标题明确当前横轴位置；可滚动内容不要再截断名称或静默隐藏系列。
- 在命中目标附近定位，留出小间隔，不盖住锚点；右侧/底部空间不足时翻转或夹取。限高按画布与视口确定，不照抄固定像素值；筛选后清掉旧读数。

**验收**：使用用户报告的密集场景，先选一条线，再换另一条；进入浮层、滚动到末尾条目后回到图中重新命中；检查标题、数值和焦点仍对应当前数据。用真实滚轮/触摸或键盘确认内容确实滚动，检查浮层在目标附近、没有盖住目标点、手机无整页横向溢出。不要只以 `overflow:auto` 存在或画布变大为完成判据。

默认保留悬浮体验；固定图下/侧边详情只有用户明确要求或认可时才采用。用户要求解决遮挡，不等于授权改变信息的呈现位置。

## 3. 筛选就近：降低来回滚动

**常见问题**：顶部筛选与目标图表隔着多个内容区，筛一次需要上下往返。

- 图头附近增加关键维度的紧凑筛选，默认与顶部共享同一状态；清楚写“与顶部同步”。
- 全部/无选择/部分选中、搜索、reset、刷新后选择都要双向一致；不是简单复制 DOM 后分别维护状态。
- 真正独立范围的组件可以独立筛选，但标题和说明必须标明控制范围。
- 过滤重绘别意外滚回顶部、丢失焦点或改变展开菜单位置。状态尽量按项目惯例保留。
- 局部筛选、sticky 筛选条二者选最简单有效的一种；不要为一个远处图表把整个顶部工具栏重复一遍。
- 多选弹层在桌面/手机都靠实际锚点布局，防裁剪并支持 Esc/点击外部关闭。

## 4. 占比与趋势图：柔和强调，数值清楚

- 主要系列占比很大时，偏好用**浅薄荷/浅色高亮渐变**强调长色块；其他系列用协调的蓝/紫等色。大块不靠深色压住全图。
- 堆叠排序和图例保持稳定；hover 有色点、实际数值，选择联动见模式 1。
- 比例趋势偏好平滑曲线，原始点在 hover 时显示。平滑不应产生超出合法范围的视觉数值。
- 空时段若确认采用补零显示，应在 tooltip 标注“补零/暂无数据”；未确认时不要擅自把未知值画成真实 0。
- 展示补值、真实观测值和汇总指标在界面上需可区分；平滑与补值是呈现选择，不应让读者误判数据。
- 浅色颜色区块的边界仍需看得见；不要仅靠颜色区分系列，保留标签与键盘可读信息。

## 5. 状态时间轴：长、细、可解释

- 本节面向密集历史；少量离散采样且每格承担跳转/预览时，按 [S02](scenarios/preview-workbench.md) 保留较宽点击块，两种设计共存。
- 细矩形、微圆角、规律小间距；历史向右变新，默认看最新，必要时可横向查看很长历史。
- 名称和摘要固定在左侧；提供时间范围、跳到最新、图例、悬浮时间与状态原因。
- 已确认色系起点：绿色 `#39bc91`、黄色 `#edbc53`、红色 `#ea7184`、未知灰 `#e4e9f0`。用文字补充语义。
- 多对象或多维度视图要明确分组与筛选范围，标题、摘要与灯带内容保持一致。
- 颜色对应的状态名称在图例和详情中解释；时间范围与单格时间尺度清楚可见。
- 未知区间留灰，与明确的正常状态区分；不要用绿色填满没有记录的区域。
- 历史不足时用独立演示数据检查长时间轴效果，展示时明确它是预览。

## 6. 全站风格与响应式

| 问题 | 解决 |
| --- | --- |
| 一个页面改好了，其他页还是代码框 | 从共享 tokens、基础 input/select/button、导航与表格改起，检查专用 CSS 是否再次覆盖 |
| 明明是比例字体，字段仍有代码感 | 同时检查字重、边框、底色、圆角和空间；不是只把 `monospace` 替换掉 |
| CSS 字体规则到处覆盖 | 优先就地修改源规则；真实代码组件与产品控件分开设定，不重新定义 mono token 来伪装 |
| 表格太宽导致整个页面横向滚动 | 表格容器局部滚动；简单键值表手机上改自适应列，让键和值同时可见 |
| 日期选择器在手机挤压 | 时间范围占一整行，起止日期双列；检查原生图标与文本空间 |
| 拖拽列表改样式后手柄不好抓 | 保留 Pointer Events/原有排序，检查目标命中和滚动；预览只改草稿，不自动 Save |
| 视觉变淡后不可访问 | 对比度、焦点、触摸命中区、键盘与 reduced motion 一起复验 |

验证用真实截图和操作：桌面、平板约768px、手机约390px；这些是经验检查宽度，不是业务必须采用的断点。

## 7. 每日时间点：24 小时制与整点默认

T10 的落地方式：

- 小时显式显示 `00–23`，分钟以两位数显示；打开新增控件与完成一次添加后，分钟回到 `00`，用户仍可主动选择 `00–59`。
- 原生 `input[type=time]` 的序列化值是 24 小时制，不代表浏览器可见选择器也是；`step=60` 只表达分钟精度，不能强制显示制式或默认分钟。仅设置 `lang` 也不足以跨环境保证显示。
- 优先使用已有、可明确设置 24 小时制的时间控件；没有时用两个原生 select 即可，不为此引入日期库或自绘滚轮。
- 小时可以保留“小时”占位，分钟预设 `00`。没有选小时的默认值不能在“保存”时悄悄添加 `00:00`；主动选择小时 `00` 则是合法午夜。
- 已保存的非整点时间原样保留。清空/暂停应同时清除待添加小时，避免保存时又自动加回；关闭不保存不修改正式设置。
- 复验：午夜、`23:59`、只选小时得到整点、重复添加去重、排序、添加后重置、直接保存、清空后保存、重新打开、键盘及小屏。
