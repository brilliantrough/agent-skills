# 全量评测估时：短测真实工作，不缩短计算语义

交付四件事：**采用哪条路径、全量预计多久、哪些是实测、还缺哪些成本。** 本 skill 不比较算法精度，也不借估时重开性能研发。读完本入口即可执行；抽样与计算细节见[计量与外推](references/measurement-and-extrapolation.md)，失败时查[真实踩坑与案例](references/pitfalls-and-example.md)。

复用时把完整的 `eval-time-estimate/` 目录复制到宿主的 skills 位置，保留 `references/`。加速依赖 `pytorch-perf-tuning`：已有路径且证据适用就直接复用；缺该 skill 又确需新优化时，显式补上依赖，不在本 skill 内另造优化流程。

## 1. 先固定估的是什么

- 从项目记录找模型／checkpoint、算法／量化版本、任务与完整题数、提示／评分协议、环境、设备放置及实际运行入口。未知事实先查；只有影响估计目标的选择才问用户。
- 明确估计范围：只评分、已有工件的一次完整运行，还是包含首次下载／校准／量化／编译。可复用的准备与首次生成工件分开；没测的成本不能默认是零。
- 写明短测预算、允许设备、需要的估计精度与停止条件。优先复用适用的既有加速；缺证据时先用 `pytorch-perf-tuning` 完成有界选路和真实调用验收，再固定配置估时。
- 加速实现随模型而变：**不默认 Graph、某个 batch、某种 attention、双卡或 HiF8。** 已验路径不因换题量／会话重复调优；本轮不要求新 profile 或写 kernel。
- 在现有任务记录里保存采用的命令／配置、版本及范围。估时授权只覆盖短测：启动全量、改公共默认或升级依赖需要另行授权。

完成判据：目标全量、选定执行路径、冷暖范围与短测预算明确。

## 2. 先规划完整工作，再少量抽样

- 尽可能用实际评测器在 CPU 上构建请求、分词和完整 batch 计划；已有同协议请求可复用。代价太高或做不到时说明缺口，不用想象的平均长度代替实际分布。
- 保留真实数据、few-shot／模板、dtype、量化粒度／统计组、KV、停止规则及生成预算。**只减少题量或完整作业数；不裁长提示、不改 `max_new_tokens`、不改算法来凑速度。**
- 计数单位跟真实调度一致：题数、选项请求数和模型 forward 数分开计；保留上下文去重、等长分桶、padding、尾批、路由和实际流水线。
- 按任务／计算形态及必要的长度、batch 类别分层，小量覆盖主要工作与高风险尾部，不必给每个学科／每个 shape 建格子。抽样与每层权重不按“哪种方法快或答对”挑选。
- 生成按完整 batch 测：batch 耗时受该批最长提示、最大实际生成步数、EOS 及 padding 影响，单题平均生成长度代替不了批次停止行为。
- 核对样本的真实 doc／prompt／target 与完整计划，显式样本索引按框架约定排序。子集重建 few-shot 可能改变提示：保留原生行为并披露，不称作与历史全量同题同提示。

完成判据：知道每层全量有多少完整作业、抽了哪些、样本如何代表全量；未覆盖部分明确列出。

## 3. 首先排除“前几批快，后面跑不完”

- 激活项目指定环境，核对实际 import 版本与数据／准备工件；运行中不同步依赖。读取厂商设备工具，使用本轮允许且空闲的设备，显式设置可见设备。
- 先在**同一模型进程**里跑代表性的较重 prefill／生成及连续批次，另核尾批／回退路径。已有适用的数值证据可复用，但仍要核对本次量化／算法覆盖与评分有效性。
- 逐批记录实际 shape、生成步数／cap、耗时，以及参与设备在边界同步后的 allocated／reserved／峰值。Graph 重放、fallback 和新 capture／JIT 按实际日志核对，不只看开关名。
- 暖机与新 shape 缓存会让显存正常增长；同类批次反复运行仍持续上涨时，先查引用／cache／图 buffer 寿命。不要靠每批重启进程掩盖累积，也不能按 OOM 前几个快批次外推可用全量。
- OOM 先区分容量、活引用、缓存及外部占卡。需要拆批／换 batch 时保留完整输入和独立统计语义，记录新 setting 并重测受影响部分，不混接旧 setting 的时间。
- `gc.collect()`／`empty_cache()` 只在证据支持时做有界验证，不作通用默认；后者不释放仍被引用的活张量。一旦采用，最终评测也要采用，回收时间计入 wall。
- 出错时保留日志和失败结果，新尝试用新目录；连续失败先定因，不反复重载大模型盲试。预算耗尽就交付阻塞和缺口，不填虚构的总时间。

完成判据：连续批次内没有未解释的持续增长／失败，预期加速确实执行，输出和算法覆盖有效。稳定要看连续批次。

## 4. 预热后计真实wall，冷成本另记

- 模型复用在同一进程中，经真实评测入口预热，覆盖本轮 batch／shape 和实际的 HF／框架生成路径；teacher 短 decode 之外仍要跑完整生成。
- 取少量完整批次或连续作业块，先预热一轮，再计至少两轮，保留各轮原值。不设所有模型通用的秒数／波动阈值，以是否足够支持本次预算判断为准。
- 隔离会跳过模型计算的响应／评分结果 cache；保留正式路径的请求去重与权重／编译缓存。核对每轮实际 forward／generate 作业数，防止第二轮只读答案缓存却报为稳态吞吐。
- 计时包含实际输入准备、输出消费和必要同步；host 单调时钟在边界等待全部参与设备。不逐 token 额外同步，不插入 profiler，不用累计 kernel 时间代替 wall。
- 分开记录加载、冻结工件应用／离线准备、数据构建／分词、首轮编译／capture／预热、稳态评分与回收。checkpoint 的实际加载时间单独测，复用 bundle 的内部 load 字段是另一个量。
- 同类批次后轮仍显著变慢、显存仍涨或不断新编译时，稳态尚未证明。只补能区分问题的少量测量；不挑最快一轮，不删慢批次。
- 短任务也计冷成本。“首轮减稳态”只是首轮额外开销，不能全归为纯编译；嵌套在预热里的 capture 字段不重复相加。

完成判据：有稳定的实测块、可解释的轮间差异和互不重算的阶段成本。

## 5. 按完整工作量外推，不把未知藏进平均数

对执行类别／层 `h`，全量完整作业数 `J_h`，每轮抽测 `m_h` 个作业，`R` 轮稳态块时间 `t_h,r`：

$$\widehat T_{\mathrm{score}}=\sum_h\frac{J_h}{m_h}\left(\frac1R\sum_{r=1}^R t_{h,r}\right).$$

- 简单按题数 `T_sample × N_full/N_sample` 只用于 batch 构成、长度、去重及生成停止行为足够可比的情况；否则按真实 batch 类别／任务分层。假设与盲区随数字一起报告。
- 共享模型的一次加载／准备只加一次，正式流程按任务重启则按真实次数计算；串行任务求和，重叠阶段按真实 wall 计，独立倍数不相乘。
- 数据／评测固定成本、短流水线的填充排空和逐批回收按实际调用次数处理；短测特有的暖机或固定开销不按题数放大。
- 热态总时间另加实际会发生的加载／准备、数据和冷开销，各项只计一次；[细则](references/measurement-and-extrapolation.md)区分三种启动场景。
- **全量未见 shape 的 JIT／capture／fallback 成本不等于零。** 没有证据时写“已测成本之和＋未覆盖成本”，不称冷启动上界，也不自动编译全 shape 来补洞。
- 同样本双轮的最小／最大只表示计时波动，不是采样置信区间；生成长度、长尾比例、冷缓存覆盖及资源争用另列敏感性。区间来自这些敏感性，固定百分比没有依据。

完成判据：每个乘数／加项都能追到实测或明确假设；有点估计、范围含义和未覆盖成本。

## 6. 验收后收口，留下一次能直接复用的入口

- 验收只认本轮真实进程身份、新鲜日志和匹配输入／源码的实测结果：运行中核进程，结束后核完整样本／输出、评分、算法覆盖及计时。**启动成功、计时器唤醒、进程结束、报告非空、残留的 completed 标记都不能单独证明完成。**
- 长测用宿主原生后台和完成通知；需要自定义下一步才配 `later`。唤醒后先验结果，不 sleep／轮询，不默认建 systemd 服务；中断后从已保存的证据判断，不猜完成。
- 在已有 run／报告里保存原始轮次、实际配置、各层计数／抽样方法、阶段成本、公式及复跑入口；大日志留在项目里，不为保存过程建 hash／manifest 台账或新评测引擎。
- 最终先报总时间，再列主要阶段与实测范围；写明“短测外推／非全量实测”、采用路径和未闭合项。短测不证明新精度、全量达标、跨模型同速或长期稳定。
- 足够支持排期即停。后续全量必须实际使用已测路径；探针里才有的拆批／回收／图适配尚未接入公共入口时，明确写出该入口限制。
- 用 `save-mem` 原位维护项目结论和风险。本 skill 为经验演化型：出现真实误估／故障才补对应规则或案例，不按每次运行追加流水。

完成判据：另一位同学能看懂时间、条件、未知并复用同一测量口径；没有全量授权就到此结束。
