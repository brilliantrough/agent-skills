# Graph：减少逐操作下发，不改算法

触发：稳定高频片段内短kernel密集、timeline反复出现微空窗，或设备执行增量小而wall显著变长。先保留计算做小型重放对照，比直接手写融合核更容易检验“下发组织是否主导”；不保证每个负载都有收益。训练同时读[训练分支](training.md)：autograd-aware捕获，验梯度累积、RNG与更新；设备长kernel已覆盖下发时不强推图。

## 1. 分清机制再选工具

| 方式 | 主要改变 | 不自动保证 |
|---|---|---|
| CUDA／NPU Graph | 缓存设备工作与依赖，减少重复Python／框架／runtime逐操作下发 | kernel数下降、单核更快、全设备无gap、跨卡流水 |
| `torch.compile` | 后端捕获／编译表达式，可能融合、减少中间量或使用graph | 所有Python控制流被编译、没有break／重编译、所有后端同能力 |
| 厂商／自写融合核 | 合并调用，可能减少中间读写和改善设备执行 | 优于graph、真实模型快于局部Event排名 |

图约束的是捕获范围内的工作与依赖，独立节点仍可并行；不是强制所有kernel串行。通常复用固定地址／shape等元数据，tensor值每次可更新。Python分支／hook不会像eager一样每次重走，数据相关分支和副作用要显式处理。

常见Torch算子可能很成熟，小shape也可能效率差；“执行很短”与“接近最优”是两回事。若下一kernel尚未提交，缩短当前kernel不会消除那段等待。仍应以host关联和保计算对照判断，不能把所有设备空窗都算CPU。

## 2. 最小接入路径

1. **选边界**：真实调用里的连贯稳定片段，输入到消费接口清楚。可包含多个库算子／Linear，而非只捕获最终QDQ；增长KV、改变shape或host控制的路由／停止、I/O和暂不支持的通信留图外。只有路由值变化、shape固定时仍可试捕获整段。
2. **查实际后端**：确认已安装的CUDA／NPU图接口与compile backend。先用一个真实片段试通；接口存在不证明适配，缺依赖也不等于不支持。不为尝试而升级共享环境。
3. **预建状态**：按调用者、device、stream及必要shape／stride／dtype桶准备输入／输出和依赖。桶只覆盖真实负载与必要尾批，不为所有假想shape建图。
4. **真实入口暖机**：先完成JIT，再经实际调用者预热／capture。生成须走真实generate，含padding位置规则、cache和inference／no_grad上下文；手造teacher输入不够。
5. **变值验证**：多组真实输入、规则／参数变化、输出消费与cache历史，防止固定buffer误读旧值。动态统计保留在线计算，不能因图地址固定就缓存统计结果。
6. **冻结后A/B**：输入copy、graph replay、必要输出clone／等待均计入；计时窗无新capture／编译。比较实际片段和完整任务host，冷建成本与稳态分报。
7. **必须回看并接着决策**：下发API／空窗是否下降、算法设备任务是否仍在、现在什么阶段主导？图间仍碎片化且影响目标，就扩大相邻稳定边界；设备热点或其他阶段成为主导就换层次。**“已经用了Graph”或“图已变快”不能结束整轮**，按主入口第6节继续或有据收口。

这是操作顺序，不要求每次新写捕获框架；复用项目可靠封装与后端工具。支持不了的shape在窗外选择可信回退并记录；不能为了成绩静默跳过工作或在计时内偷偷新建图。

## 3. 容易漏掉的实际成本与正确性

- **所有权**：图输出可能下一次重放就被覆盖；固定输出按调用者／stream管理，消费者尚未完成时不能复用。需独立结果就clone，并把成本算进去。
- **跨上下文**：inference-mode创建的持久tensor，之后仅no_grad不解除原位写入限制；需要跨模式时用`inference_mode(False)+no_grad`冷建普通buffer／图，或明确约束上下文一致。不要靠删输出复制／cache隔离绕过错误。
- **真实shape**：相同数值语义不保证shape／stride一致；padding派生position_ids、广播维度、尾批、decode与prefill都可能不同。先实际暖机，不删除frozen检查。
- **变化状态**：权重／规则更新、cache增长、RNG、梯度／optimizer与AMP按后端语义处理；保留实际捕获对象拥有的规则／scale等图外张量，退出临时评测上下文后仍需存活，不能只保留模型权重。训练静态梯度alias、sample隔离、激活寿命及更新验收见[训练分支](training.md)。本页纯前向经验不直接覆盖训练step。
- **并发与多卡**：捕获流、回放流、依赖Event与静态buffer寿命一起管理；两个线程或跨stream不能默认共享同一图状态。Graph不自动让分层模型成为流水线。
- **释放**：同步使用者后在图所属device/context内释放资源。Ascend多卡不能依赖退出时恰好处于正确device；核实际清理日志，不以进程正常结束代替验证。
- **覆盖**：Python hook／计数不一定随replay执行；用绑定、重放和目标设备任务核对真实算法工作。缺host flow不当零下发成本。
- **冷启动**：用`N×(T_eager−T_replay)>T_build`粗筛回本，前提是同口径完整调用时间且已计copy／输出；开发与维护成本另计。编译／capture不混稳态，也不从一次完整任务中消失。

## 4. 失败或无收益时怎么走

| 实际证据 | 有界处置 |
|---|---|
| 捕获包含数据相关控制／动态输出shape | 把该处留图外或用真实shape桶；保留语义，重新选连贯边界 |
| 已编译执行器绑定另一stream | 按实际后端检查在目标流绑定／暖机是否支持；成本不值时分别比较compile与手工图 |
| compile内部已捕获图，外层再capture失败 | 避免盲目嵌套，选择一层控制回放；失败只限定本版本／试法 |
| capture图很多、图间copy／包装仍占主导 | 合并可捕获片段，复用状态，计完整调用；不因“已经用图”跳到写核 |
| 长设备kernel／中间读写仍主导 | 现成融合／compile或kernel外援，附当前graph基线及目标成本 |
| 冷编译、输入copy、输出clone吃掉收益 | 计真实调用次数／完整成本后回退，别只选稳态快值 |
| host关联缺失、但重放确实更快 | 报“减少执行组织开销的证据”，保留CPU／runtime／依赖细分未知，不强凑归因比例 |

## 5. 带边界的经验

2026-11-09，Ascend 910B2／CANN9.0.0／torch2.9.0／torch-npu2.9.0.post2，GLM32同16题batch16：已验A融合＋KV小图上扩大到Norm／QDQ／投影GEMM／RoPE／MLP两段图，评分140.067481→92.228505秒（省34.1542%）。同场四步设备任务并集0.630249→0.644872秒，空窗1.474348→0.443154秒；设备任务反增，host单核下发21849→4769。支持主动扩大稳定片段，不是“所有kernel已最优”或全部gap等于CPU的证明。

首轮teacher RoPE形状`[1,1,64]`漏了真实HF生成的`[16,1,64]`；补真实generate暖机，保留计时内frozen门禁。`npu`／`npugraph_ex`独立Norm数值通过，但当前跨stream／嵌套capture试法失败，未进入模型；不外推后端普遍不可用。

来源项目报告：`docs/experiments/glm32-pytorch-generation.stage1.report.md`第8–9节，工件`artifacts/runs/20261109_glm32_graph_compile_retry1/`。路径只作证据标识，原始工件未随skill发布；通用方法不依赖读取开发机材料。该轮无全量／通用尾批／并发验收。

2026-11-11，Ascend 910B2同版本栈，GLM47已用46个MoE小图后，扩大为47层prefix／tail＋两份设备级KV QDQ图，动态cache／attention仍在图外。4步直接下发51884→3512，GMM均368，设备并集0.5314→0.5452秒；图执行184→752、设备任务反增。与prefill复用packed QDQ组合后，同8题256预算稳态评分222.6436→67.4119秒；首次暖机／校验算入中位数则230.9245→108.9869秒。不是新增DSL核收益，也不与前轮倍数相乘。详见[MoE案例](case-moe-eval.md#第二阶段扩大图复用已有prefill核)；尾批／长期／全量未验。
