# 最后一级外援：kernel-knowledge交接与接回

## 何时需要，不需要时停在哪

本skill负责PyTorch执行组织，不另设kernel优化引擎。先按[execution-chain](execution-chain.md)的应用timeline判断关键路径：下发、同步、分配和串行组织先在PyTorch层处理；真实算子／连贯片段仍是值得处理的热点，才考虑外援。不要求先试完所有框架选项，也不因允许写核就默认进入底层调参。

交接前说清：**当前主要成本是什么、希望kernel省下发／中间读写／设备执行中的哪项、为何现成框架路径不足**。若稳定小核链夹持续微空窗，先提供保计算graph／compile对照或具体不可行依据；不能仅凭kernel数量多就请求手写核。已有graph时把它作为当前基线，不能只与更慢的eager路径比较。

- 原有最终kernel不保证外围统计／定标链高效；交接完整有意义片段，不只交一个名字。
- 算法仍在研发不排除复用在线原语：参数作为输入，离线权重／校准改变不等于在线核必须重写。
- 新格式没有原生硬件支持仍可融合浮点伪量化，再接厂商GEMM；不冒充原生低位计算收益，不默认重写矩阵乘。
- 给短预算，复用已有正确候选。1.25×已经够用而追1.3×成本明显更高时，可以收口；这是取舍例子，不是最低门槛或上限。系统化kernel／部署引擎研发另立任务。

## 交给外援什么

| 交接项 | 必要内容 |
|---|---|
| 真实片段与参考 | 调用来源、连续操作、输入／参数和确定性回放；不能硬编码校验输出 |
| 工作负载 | 实际shape族、dtype、stride／布局、分组／归约轴、mask／padding及调用频次；不只报总元素数 |
| 数值契约 | 舍入／饱和／异常值／cast顺序、允许误差；动态统计不偷换分组，训练另含backward／STE |
| 调用边界 | 输入输出所有权、原地／alias限制、stream和cache更新位置；频繁变化维度与尾批单列 |
| 投入与返回 | 设备／资源、预算、目标成本和当前最佳基线（含已验graph）；返回源码、支持范围、数值误差、计时及专业证据 |

为已观测的高频shape及必要边界申请候选，不为假想模型穷举。跨模型优先共享公式、参考和实现，适配后核对新负载；不强求统一最优源码。

## 外援负责什么

- 复用已登记的`KERNEL_KB_ROOT`或宿主插件，从库内当前`INDEX.md`、`kernel-optimization-pipeline`读取工程入口和任务策略；不冻结旧技能清单或照抄历史引擎入口。
- DSL／tile／片上流水／硬件同步、候选迭代、专业设备计时、SOL和profile由外援按其当前规范执行。本skill不复制这些教程，不用一套简化循环绕过外援证据门禁。
- 需要独立上下文／资源隔离时才通过`kernel-worker`委派；外援接管后仅一个候选写入者，PyTorch主会话不同时竞争改核。用户指定的策略交由外援按其流程加载。
- 外援缺失时说明缺口，保留可信PyTorch／厂商参考或现有工具；不自动安装平台、扩大预算或编造完成。安装／版本／权限依库内现行说明。

## 接回PyTorch后由谁验收

主会话负责接回和实得收益，不能只看“外援已完成”或局部排名：

1. **证据匹配**：候选源码、真实输入、支持范围和误差／time／SOL／profile证据对应；新鲜日志与实际结果齐，计时器、启动、退出码、旧状态不能代替完成。
2. **功能边界**：回放真实层输入、尾批／布局／统计分组；未支持shape回参考或明确报错。不要默认私有入口支持任意alias、并发或数值域。
3. **状态与依赖**：固定输出／graph缓冲按调用者和stream管理，检查输入copy、输出消费与寿命、跨流依赖、KV历史不被覆盖；inference／no_grad切换须实测。
4. **真实调用成本**：计入包装、绑定、输出构造／copy、冷编译和准备；局部Event可能含下发空窗，专业计量沿用外援合同，不能与graph或整模host时间混算。
5. **保留或回退**：共同入口做有界同输入host对照，覆盖计时与评分，不能乘分散倍数。正确且等待够用就冻结；不因低利用率、单核仍有余量自动续调。

一般PyTorch判断回本skill；专业实现／平台经验回领域维护源。原始工件留来源项目，不在这里保存另一套kernel工程正文。

## 2026-10-19 真机教训：不是所有“简化”都会快

以下保留历史条件与反例，只解释为何以真实调用收益取舍；不是要求后续Agent照表调tile。专业实现与最新知识查外援。

Ascend 910B2 / PyTorch 2.9 / Triton-Ascend 3.2.1，固定尺度 BF16 QDQ；以下是 Event 图执行微基准，其他机器需重测：

| 尝试 | 观察 | 决定 |
|---|---|---|
| tile 1024→4096，大张量 | HIF8 约 334→164 μs；E4M3 约 315→117 μs | 保留大 shape 候选，小 shape 另看 |
| 除以 2 的幂→乘精确倒数 | 穷举正确，但比已调 tile 略慢 | 回退，不因指令看着少就保留 |
| 小张量继续抠核 | 设备几 μs，普通 Python 调用约 130 μs | 先解决下发，不能许诺同倍数应用收益 |
| PyTorch `ldexp`→tensor 位操作 | 真实输入逐值相等，却更慢 | 后端实测优先于算子名称直觉 |

原始输入、脚本和完整表留在来源项目的 `docs/experiments/fakequant-fusion-event.probe.report.md`；可移植 skill 不依赖这些本机文件执行。该轮只覆盖有限值、连续布局、标量尺度前向。

同日分型接入（来源项目`docs/experiments/hif8-kernel-integration.report.md`）：
- 独立scalar/row/channel/expert/masked-row核，σ参数和逐行范围另核；保留原方差与专家归约
- GLM同8题host A/B/B/A：评分68.51→54.59s，eval102.71→88.43s，逐题响应一致
- 逐行核沿用标量核的4096 tile会UB溢出，改2048；按形态调参，以整模实得收益收口。训练与其他工作负载另验

完整收口／回看规则见SKILL.md“验收、回看与停止”。设备核已短、模型仍慢时回到PyTorch调用／timeline，不沿原DSL惯性继续调。需要改变舍入、统计组或精度的方案另记算法对照，不冒充执行优化。
