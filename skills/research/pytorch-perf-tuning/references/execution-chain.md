# 从新增执行链定位减速：设备计算、下发还是依赖

适用：便宜的浪费已处理仍慢；量化、归一化、路由、adapter或hook引入明显减速；已有kernel／小图，整段仍慢。进入更深优化前主动读timeline；复用有效采集，只做能区分当前假设的短对照，不照抄整套消融矩阵。

## 1. 固定问题与比较口径

- 同模型、准备后的W／变换、真实输入、batch、后端与调度；分列加载、冻结准备、冷编译／预热、prefill、decode和评分。
- 隔离decode可固定teacher token／步数，但它不是官方greedy或质量评测。组合候选须接回真实任务，包含停止、变化的KV长度、padding和输出消费。
- 绕过在线步骤但保留SQ／已量化W，叫“同准备模型的在线关闭对照”，不是原checkpoint BF16。
- 不以不同setting的logits／生成／分数相同为提速门槛；同组统一setting，实现数值、统计轴、独立性、覆盖与评分仍验。

## 2. 展开执行链和调用放大

画真实调用者：输入／hook→统计→参数／mask→scale、center、cast→变换→库算子→cache／输出。记shape、dtype、stride、归约轴、频次和临时量。

- 单次便宜也会被层／专家／head×生成步数×请求数放大；先估调用量，再由短trace核对，必要时最小开关复现因果。
- `tensor/as_tensor(Python值, device=...)`可触发同步复制。静态规则按身份／device／dtype复用；规则／模型变化时失效，动态均值方差不能缓存。
- 完整组可省count／尾mask；尾组和padding保留原处理，不能偷换中心化方差、舍入或真实归约组。
- 最终变换已有Triton／TileLang，不代表统计／定标也融合；grouped名也不证明设备批量dispatch。先查覆盖，不重复造核。
- 自写核设备已很短时，再量真实调用包装、输出构造、绑定、输入copy和消费；片上`alloc_shared`不等于在线分配GM，`empty`也不保证每次物理HBM分配。

## 3. 主动读三层timeline，再区分整段与局部瓶颈

热点表回答“哪些kernel累计耗时”，不能回答“为何kernel之间没工作”。不能只报一个空闲百分比，等用户自己请求画图、观察并选工具。

1. **选窗和核覆盖**：实际PID／物理设备，相关host线程、runtime API、计算／copy stream齐全；标prefill／decode或训练阶段。给明确定义的首尾锚点，排除是否由采集启动／结束拖高。
2. **全窗→局部**：看任务是长段运行还是密集短kernel夹空白，再放大典型微间隔和最长等待。比较首尾与窗内、几个子窗，区分持续模式与少量离群点；有展示需要时导出真实总览＋局部图。
3. **上下关联**：在device结束当前任务、下一任务开始之间，看host是否仍准备／launch，runtime是否同步／复制，其他stream／设备是否有前驱。观察到先前任务结束、下一launch尚未到达，才支持供给不足；已launch未运行则进一步查队列／依赖，而非只怪Python。
4. **给出动作**：说明阶段、模式、证据强度和一项可区分假设的改动。关系缺失时保留未知，稳定链可用保计算graph对照；不因不能精确区分CPU和runtime就跳到设备调优或无限追因。

同一采集窗内，定义相关设备任务区间的并集`U`，共同无记录任务时间`G=T_window−|U|`。多卡分别报各卡忙区、交叠与共同空白；**G不是CPU时间，更不是可回收时间**。kernel Duration相加可重复计重叠，不能当`|U|`或wall。

Gap分布至少足以回答“持续微间隔还是少数长等待”：按需要用段数／中位／尾部／最大值及首尾占比，不为填表每次算一整套统计。微间隔多且高频稳定链下发滞后，下一步应主动graph；长等待则先找同步、I/O或真实依赖。

| 共同证据 | 优先调查 | 不可直接推断 |
|---|---|---|
| 阶段wall与长kernel／任务占用一起增加 | 访存、归约、布局、program粒度及中间读写 | FLOP少就便宜，或只能优化CPU |
| wall大涨，设备执行增量小、各卡共同空窗长 | 下发、调度、同步、I/O、分配和依赖 | 所有空窗都是Python计算或都可消除 |
| 显式同步已减，仍有密集小kernel与微空窗 | 连续eager链及其调用放大，优先保计算graph对照 | 缓存标量能解决全部延迟，或必须先写核 |
| 已有局部graph／融合核，图间仍密集空白 | 扩大连贯稳定片段，查copy／包装／graph break | “已经用了graph／kernel”说明整链已优化 |
| D2D短、host在复制处久等 | 上游计算、源／目标stream依赖、重复mask／position | 数据经CPU中转，或DMA时间就是通信成本 |
| 低AICore、低阶段HBM带宽，空窗长 | 下发／依赖与小工作量并存 | 整段已memory-bandwidth-bound |
| 设备连续有工作，同层级有效带宽接近匹配锚点 | 带宽／流量、复用和布局 | 所有算子都受同一资源限制 |

同窗对齐阶段、runtime及所有相关流／拷贝。多卡看任务区间并集，不能把累计kernel时间当wall或MFU。host API可与设备执行重叠；`non_blocking=True`不抹去真实依赖，源码无显式同步也可能后端等待。

BF16权重读占主导的小batch GEMM近似`I=2BKN/(2KN)≈B FLOP/B`；它描述局部，不证明整个评测把HBM跑满。结合实际M/N/K、缓存、字节及时间线判断；小GEMM偏访存与整段下发受限可以并存。大GEMM持续重放只校验该负载能力，不是整模利用率及格线。

低频监控须与真实阶段对齐，不在热循环同步。短prefill可能只采到几个点，窗口跨界或字段采样滞后时不能定因。HBM容量使用率、带宽使用率、任务覆盖、MFU、pipe活动率各自报告，不混分母。

低层／私有入口可能绕过profiler的host挂钩；有设备任务但缺host flow起点时，不把缺记录当零开销。分别声明设备覆盖与host关系覆盖，后者不完整就不计算队列／待发份额。

## 4. 让归因决定优化层次

先问本轮要减少哪项：**下发次数／host执行、同步与依赖等待、中间读写、设备执行时长**。融合既可能省launch，也可能省流量／设备工作，不能只凭“写了核后变快”判断是哪一项。

在非重叠简化模型中，只有可缩短的设备关键路径占总时间`f`时，把该部分加速`r`倍的整体上限为`1 / ((1−f)+f/r)`。`f`不能用累计kernel Duration或`1−共同空窗比例`直接替代；这只用于判断投入量级，不作性能承诺。CPU还没下发下一任务时，继续缩短当前小核往往不能缩掉关键等待。

| 对照／工具 | 保持／改变什么 | 接回检查 |
|---|---|---|
| 完整链／逐模块绕过 | 固定输入和准备状态，查边际贡献 | 绕过改变数值／cache，只作归因，不当候选 |
| 仅统计／统计＋参数／仅最终变换 | 区分外围链与核的量级 | 固定参数不是动态链的精确分摊；差值不硬凑100% |
| 静态复用／批量组织 | 减重复构造、搬运和逐项调用 | 动态统计、分组和mask不变 |
| CUDA Graph／NPU Graph | 保留计算，压缩逐操作下发 | 真输入更新、copy、输出alias／寿命、stream和shape缓存；未必减kernel数 |
| `torch.compile` | 编译可支持的表达式／控制流 | 实际设备backend、graph break、重编译及下发；不等同graph |
| 厂商／自写融合kernel | 减launch、中间读写或改设备组织 | 原统计／舍入／布局契约；局部→完整片段→模型各自实测 |

- 下发线索明确且片段稳定时，主动做保计算graph／已适配compile小对照，或记录具体不可行依据；不只是把三种工具平铺让用户选。稳定片段可包括库算子／GEMM，不限于统计／变换；不为捕获关闭必要KV或改统计组。
- 管理图边界而非强求整模图：增长cache、停止控制等留图外，输入更新和输出消费仍属真实成本。已有小图后残余等待仍影响目标，再查图间断点并扩大一段。接入见[graph-replay](graph-replay.md)；手写kernel需要时交外援，不在这里转入DSL调参。
- 编译／capture在稳态窗外，冷启动另报；变输入验输出，计时中图／绑定不增长。图重放时Python hook／计数未必重跑，不能拿Python次数替代设备launch。
- 单核排名不代替模型wall；输入copy、输出消费、库边界和包装都计入。保存原值，少量同卡交错复测，不挑快轮、丢慢首批或相乘分散倍数。
- 参考执行与候选命中计数分开；校验本身不能被计为生产prefill／decode。有限logits／cache长度不是完整数值或评分验收。

## 6. 停在足够决策的证据

真实调用契约、覆盖和host收益已验，且等待已支持研究，就冻结可靠路径；若仍阻塞目标，回看剩余关键路径，允许由设备优化转到graph，而非沿原工具继续调。正式质量／全量速度只在授权任务中验证；残余空窗／低利用率本身不自动开启矩阵、写核或推理引擎。下一项只选影响研究等待、且已有证据支持的链；通用经验回本skill，专业平台与kernel经验回领域维护源。
