# 多卡评测：让不同完整batch重叠

仅在模型跨卡、阶段串行是可行动等待来源时使用。优先复用现成调度；下面是无cache似然评分的轻量适配经验，不要求每个模型都实现流水线。生成的KV所有权需另验；训练先读[训练分支](training.md)，区分DDP、分层驻留与真正流水线，保留反向／更新及激活寿命契约。

## 先分清放置、计算与调度

- `device_map="balanced"`等通常按层分担模型存储；一批数据依次走过两卡，不等于启用了TP或流水线调度。
- 对同一batch，前后层有依赖；对不同batch，可以让前段处理下一批、后段处理上一批。
- 看实际设备时间线：交替计算、两卡共同空白、传输等待是不同现象。分卡本身不能证明通信是主因，流水线也不会自动消除阶段内部的小核／同步开销。
- D2D数据与host等待源／目标流分开；DMA短不证明等待短，host等复制不证明数据经CPU。需隔离时用同一可容纳模型单卡／分卡短测，不跨模型定因或默认换FSDP。见`execution-chain.md`。
- 记录每段计算与传输、实际batch/长度和峰值。只有阶段明显失衡且值得处理时，再按真实工作量调整切分；层数相等不保证时间相等。

## 保留原批次，先做有界重叠

```text
设备A：前段(batch 0) → 前段(batch 1) → 前段(batch 2)
设备B：               后段(batch 0) → 后段(batch 1) → …
```

- 优先调度原来的完整batch，不先把batch8拆成更小microbatch；拆小会改变专家矩阵规模，还可能改变定标、padding和评分口径。
- 各阶段有独立下发者；两线程可作为低成本候选，不把“一卡一进程”当必需条件。只有实测显示线程/GIL限制，才考虑独立进程或框架调度，成本计入预算。
- 队列有界；两阶段可从少量在途batch开始，记录额外激活、logits和工作区峰值。不要无限预取或为填满设备重复无用任务。
- 显式设置各worker当前设备、执行流、inference/AMP上下文。`ContextVar`等样本形状／定标状态不会因为提交任务就自动正确传入；在worker设置并在退出时恢复。
- 若阶段使用graph，各worker在实际stream及调用shape下预热，独立管理静态buffer／输出寿命；不能因串行重放通过就认并发安全。生成另需每batch独立KV、位置、停止状态与token反馈；不能在两个线程分别进出会覆盖共享forward的上下文。图边界见[graph-replay](graph-replay.md)。
- 跨阶段用设备支持的Event／流依赖；需要时采用清楚的同步交接。`non_blocking=True`不是依赖证明；源tensor保留到异步拷贝读源结束，目标tensor保留到消费完成。
- 复用模型原层、position/mask、旋转和KV wrapper；共享分支、router补偿不能漏。异常应通过future／进程结果返回，不能把部分输出算完整批次。
- 后段输出可在最后一张卡完成评分，再回传小结果；避免全词表logits往返。但这一改变与重叠调度分开对照，不能把总收益全归给流水线。

## 两次对齐，再看实际收益

1. **原模型→阶段串行**：固定权重、dtype、输入、mask/分组与cache口径，小样本检查输出及完整覆盖。拆阶段若改变结果，先解决；不靠总分相同宣称等价。
2. **阶段串行→重叠**：同一切分、同一批次顺序、同一GMM／QDQ后端。先验证批次身份、逐选项响应和统计上下文，再按约定范围做host端到端对照。
3. **真实性**：短trace确认两设备真实任务重叠，核对层／算子计数；profiler开销不计入性能对照。两个线程存在、队列非空或两卡有显存都不能替代重叠证据。
4. **收益**：真实评测记录加载、准备、评分和总耗时，host计时边界等待相关设备；短测必要时交错复测控制预热顺序。不是把各阶段Event耗时相加或只报最忙区间。
5. **收口**：正确且可靠加速就保留；线程方案已够用，不自动再做多进程、TP、专家并行或完整调度框架。

## 测速边界

- 填充／排空是实际成本。只有少量batch或长输入导致批次数骤减时，短窗口吞吐不等于稳态吞吐；报告批次数，不能把所有差异归因于单batch计算。
- 固定形状重复输入、热缓存、去掉harness请求处理的探针，只能回答相应问题；不能代替真实评测时间。
- 更高瞬时利用率不是验收目标。流水线可能明显缩短总时间，AICore仍低；反过来，看到重叠也可能没有净收益。
- GMM、Triton核、流水线分别胜出，不保证组合自动更快或正确；整合后做一次有界同输入验收，不相乘独立倍数。
- 只认可本轮实时进程、匹配源码／输入的新鲜日志和实测结果；启动成功、计时器触发、进程结束或残留状态文件均不能单独证明完成。
